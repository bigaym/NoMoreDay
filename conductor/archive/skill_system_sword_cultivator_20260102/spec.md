# Specification: 剑修核心技能系统与星盘联动

## 1. 概述 (Overview)
本 Track 旨在为《NoMoreDay》建立主动技能系统基础架构，并重点实现“剑修”职业的核心机制。核心挑战在于将主动技能与现有的标签驱动伤害流水线（Damage Pipeline）以及星盘（Astrolabe）被动系统深度整合，实现“标签感知的动态属性缩放”。

## 2. 功能需求 (Functional Requirements)

### 2.1 技能基础架构 (Active Skill Infrastructure)
- **技能组件 (`SkillComponent`)**: 支持 5 个主动槽位 (Q, W, E, R, RMB)。
- **混合驱动模式**: 
    - 使用 JSON 定义基础数值（伤害倍率、基础点伤、冷却、法力消耗、标签）。
    - C++ 实现特定的动作逻辑钩子（如位移轨迹、引导逻辑、施法动作状态机）。
- **冷却与资源管理**: 基础的冷却计时器与法力（Mana）扣除逻辑。

### 2.2 星盘深度联动 (Astrolabe & Tag Integration)
- **标签感知缩放 (Tag-Aware Scaling)**: 
    - 升级 `StatsSystem`，使其能够根据技能标签（如 [Physical], [Melee], [Sword]）动态计算最终修正。
    - 在星盘中支持“按标签加成”的节点类型（例如：+10% [Physical] 伤害）。
- **关键天赋支持 (Keystones)**: 实现“剑心通明”等关键节点对技能底层机制的修改（如：单手剑伤害加倍）。
- **标签转换逻辑**: 支持通过星盘或技能配置进行的伤害类型转换。

### 2.3 剑修核心机制 (Blade Ascendant Mechanics)
- **剑意资源池 (`SwordIntentComponent`)**: 
    - [近战] 击击获得层数，上限 10 层。
    - 消耗剑意可增强后续技能的数值或形态。
- **影子施法框架 (Shadow Casting)**:
    - 实现一套机制，允许生成一个临时的“残影”实体来执行技能逻辑，而不阻塞玩家本体的操作。
- **职业资源恢复**: 实现“击中回蓝 (Mana on Hit)”逻辑。

## 3. 技术实现要点 (Technical Details)
- **ECS 设计**: 
    - `ActiveSkills`: 存储玩家当前装备的技能 ID 和状态。
    - `SkillData`: 通过 `ItemFactory` 类似的注册表加载 JSON 数据。
    - `ShadowCastTag`: 标记由残影释放的技能实体。
- **伤害流水线对接**: 确保技能释放时生成的 `DamageEvent` 携带完整的标签快照。

## 4. 验收标准 (Acceptance Criteria)
- [ ] 玩家可以装备并释放至少两个原型技能：“流云刺”（位移+近战）和“裂空斩”（远程剑气）。
- [ ] 技能伤害能正确响应星盘中对应的 [标签加成] 节点。
- [ ] 连续攻击可累积“剑意”，并在 UI 或数值上有所体现。
- [ ] “残影”能正确独立释放技能，且不消耗玩家本体的动作帧。
- [ ] 击中敌人时，法力值按预期回复。

## 5. 出色范围 (Out of Scope)
- 复杂的技能专精树 UI（本阶段仅实现后端逻辑支持）。
- 全职业所有技能的实现（仅限剑修原型）。
