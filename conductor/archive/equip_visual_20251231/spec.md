# Track Specification: Equipment Visual Enhancement and Randomization

## Overview
This track focuses on fully integrating the recently automated equipment asset registry into the item generation system. We will ensure that every item generated by the `ItemFactory` is assigned a random, type-appropriate icon. Furthermore, we will enhance the visual representation of item rarity in the UI through dynamic tinting and animated borders.

## Functional Requirements
- **Explicit Asset Mapping**:
    - Update `BaseItemDef` in `ItemFactory.cpp` to include an `assetCategory` field (e.g., `"sword"`, `"pauldrons"`, `"wand"`).
    - Ensure all existing base items are mapped to their corresponding asset sub-namespaces in `assets::equipment`.
- **Enhanced Random Icon Assignment**:
    - Modify `ItemFactory` to select a random icon from the specific `assetCategory` namespace for every new item.
    - Maintain full randomness: even identical base items (e.g., two "Iron Longswords") may have different icons from the same category.
- **Rarity-Based Visual Variants**:
    - **Dynamic Tinting**: Pass the rarity color to the UI rendering logic to subtly tint item icons.
    - **Animated Glow Borders**: Implement a pulsing or "shimmer" border effect for Legendary and Mythic items in `UIRenderer::DrawSlot`.
- **UI Consistency**:
    - Ensure the `textureId` assigned at creation is correctly used by `UIRenderer` for inventory, equipment, and world-drop labels.

## Non-Functional Requirements
- **Performance**: Use existing `AssetLoadingSystem` and `constexpr` arrays to ensure zero-allocation icon selection.
- **UX**: Rarity should be immediately identifiable via both the border color and the animated effects.

## Acceptance Criteria
- [ ] Every generated piece of equipment has a random icon appropriate to its category.
- [ ] Different instances of the same base item often show different icons.
- [ ] Legendary and Mythic items display an animated glow effect in the inventory.
- [ ] Higher rarity items show subtle color tinting on their icons.
- [ ] Unit tests verify that the `assetCategory` is correctly respected during item creation.

## Out of Scope
- Fixed icons for "Unique" or "Named" items (to be handled in a future track).
- 3D model variations (this is a 2D game).
