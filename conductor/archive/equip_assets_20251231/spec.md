# Track Specification: Equipment Asset Automation and Random Icon Matching

## Overview
This track focuses on automating the management of equipment assets and implementing a system to randomly assign type-appropriate icons to items when they are dropped. We will move away from manual asset registration for equipment and use a compile-time mapping generated from the `assets/textures/equipment` directory.

## Functional Requirements
- **Asset Registry Automation**:
    - Develop a Python script (`scripts/gen_equipment_registry.py`) to scan `assets/textures/equipment/`.
    - Generate a C++ header (`src/core/EquipmentAssetRegistry.hpp`) containing `constexpr assets::TextureAsset` entries for all found icons.
    - Organize the registry by equipment type (e.g., weapon, armor, ring) based on file subdirectories or naming conventions.
- **Data Model Update**:
    - Add `entt::id_type textureId` to `NoMoreDay::ItemComponent` in `src/components/ItemComponent.hpp`.
    - Update `nlohmann/json` serialization/deserialization for `ItemComponent` to include `textureId`.
- **Random Icon Assignment**:
    - Implement a mechanism to retrieve a random asset ID from the `EquipmentAssetRegistry` based on `ItemType` and `EquipmentSlot`.
    - Integrate this assignment into `ItemFactory::createRandomLoot`, `ItemFactory::createWeapon`, and `ItemFactory::createArmor`.
- **Asset Loading**:
    - Update `AssetLoadingSystem` to ensure equipment textures are loaded into the `ResourceManager` during initialization.
- **UI Integration**:
    - Update the inventory and equipment UI (e.g., `UIInventory.cpp`) to render the assigned `textureId` for each item.

## Non-Functional Requirements
- **Performance**: Ensure random selection and texture lookup have negligible overhead.
- **Type Safety**: Leverage `entt::id_type` and `constexpr` for compile-time safety and efficiency.
- **Maintainability**: New equipment assets added to the filesystem should be automatically picked up by the generator script.

## Acceptance Criteria
- [ ] Running the Python script generates a valid C++ header with all assets in the target directory.
- [ ] New items generated by `ItemFactory` have a valid `textureId` assigned.
- [ ] The assigned `textureId` correctly corresponds to the item's type/slot.
- [ ] The inventory UI successfully displays the unique icons for each item.
- [ ] Automated tests verify that `ItemComponent` stores and retrieves `textureId` correctly.

## Out of Scope
- Implementation of a full-blown "Transmog" system.
- Modification of non-equipment assets (e.g., characters, environment) at this stage.
