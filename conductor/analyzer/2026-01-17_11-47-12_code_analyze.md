# Code Risk Analysis Report
Date: 2026-01-17 11:55:00

## Summary
本次审计针对代码库中的字符串使用（特别是类别表示）进行了深入分析。发现核心游戏系统（如 `StatsSystem` 和 `EnemyComponent`）中存在高频的字符串分配行为，这在热点路径（Hot Paths）中构成了显著的性能风险。此外，部分机制抗性由于字符串匹配逻辑缺失，实际上处于未生效状态。

## Critical Risks (High Priority)
### 1. `StatsSystem::Recalculate` 中的频繁字符串分配
- **Location**: `src/game/systems/combat/StatsSystem.cpp` 和 `src/game/components/EnemyComponent.hpp`
- **Description**: `StatsSystem::Recalculate` 函数在每次调用时都会在栈上实例化 `EnemyRace` 对象：`EnemyRace race(enemy->raceType);`。`EnemyRace` 的构造函数会为 `resistances` 分配 `std::vector<std::string>`，并为 `texturePath` 分配 `std::string`。考虑到属性重算在战斗中发生的频率，这是一笔昂贵且无意义的开销。
- **Consequence**: 在核心逻辑更新期间产生不必要的堆内存分配，导致内存碎片化压力和 CPU 周期浪费（malloc/free）。
- **Recommendation**:
    1.  将 `EnemyRace` 定义移至静态 `constexpr` 查找表（Lookup Table）或单例注册表，避免运行时重复构造。
    2.  彻底移除 `std::vector<std::string>`，改用 `Tag` 位掩码（Bitmask）表示抗性。

### 2. 抗性系统逻辑失效 (Logic Failure)
- **Location**: `src/game/components/EnemyComponent.hpp` vs `src/game/systems/combat/StatsSystem.cpp`
- **Description**: `EnemyRace` 中定义的字符串抗性（如 "bleed", "poison"）在 `StatsSystem` 中似乎被完全忽略。`Recalculate` 仅读取了数值属性（HP, Speed, Armor），而并没有处理抗性字符串的逻辑。
- **Consequence**: 游戏逻辑错误，不同种族的敌人实际上没有预期的伤害抗性。
- **Recommendation**: 引入 `Tag`-based 抗性系统。在 `Recalculate` 中简单地执行 `combat.resistances_tags |= raceData.resistances;`。

### 3. 基于字符串的词缀与类别定义
- **Location**: `src/game/components/ItemStats.hpp`
- **Description**: `AffixDefinition` 使用 `std::vector<std::string>` 存储标签要求。虽然运行时会转换为 Tag，但在加载和存储阶段仍保留了字符串。更严重的是，`Affix` 实例直接包含 `std::string name`，导致每个物品实例都有额外的字符串开销。
- **Consequence**: 随物品数量增长，内存占用线性增加，且序列化/反序列化成本较高。
- **Recommendation**:
    1.  若 `Affix` 名称是静态的，应在 UI 层根据 `AffixType` 和 `Tier` 动态生成，或存储 `string_view`/`const char*` 指向静态数据。
    2.  `ItemComponent::setName` 应优化为 `SetID` 枚举或哈希索引。

## Performance Bottlenecks
- **EnemyRace Instantiation**: 每次属性重算时的 `vector<string>` 分配。
- **String Comparisons**: 潜在的字符串比较（虽然目前 Tag 系统已大幅减少了这一点，但遗留的 `behavior_id` 和 JSON 解析仍依赖字符串）。

## Refactoring Suggestions

### 1. 静态化 EnemyRace 数据
```cpp
struct EnemyRaceData {
    float baseHP, baseDamage, baseSpeed, baseXP, baseArmor;
    Tag resistances; // 使用位掩码替代 vector<string>
    std::string_view texturePath;
};

// 静态常量表 (in Common.hpp or EnemyData.cpp)
static constexpr std::array<EnemyRaceData, 12> kRaceData = {{
    // UNDEAD
    {30.0f, 15.0f, 40.0f, 10.0f, 100.0f, Tag::Bleeding | Tag::Poison, "assets/textures/monster/skeleton_0.png"},
    // ... 其他种族
}};
```

### 2. 优化 StatsSystem
```cpp
// 在 Recalculate 中:
const auto& raceData = kRaceData[static_cast<size_t>(enemy->raceType)];
calcs[...].base = raceData.baseHP;
```
