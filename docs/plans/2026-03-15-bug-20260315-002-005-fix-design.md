# BUG-20260315-002~005 Fix Design

## Context

2026-03-15 的静态核查表明，`conductor/bug_registry.md` 中 `BUG-20260315-002` 到 `BUG-20260315-005` 的原始根因记录都只“部分正确”。

- `BUG-20260315-002`：掉落丢失的容量截断链路已确认，但“缺少 compute barrier”不成立，闪烁的第二根因仍待运行时复现。
- `BUG-20260315-003`：拖拽换装/换包失败与目标槽丢失都成立，但装备与扩展包的失败路径并不相同。
- `BUG-20260315-004`：主字体缺少 `U+1F9F9` 只是背景条件，按钮渲染绕过 emoji fallback 才是直接触发点。
- `BUG-20260315-005`：问题不是“没有唤醒路径”，而是 dormancy 唤醒阈值与再次休眠阈值不一致，同时 aggro 受双门控压缩。

本设计只定义修复方向与验证策略，不在本轮直接改代码。

## Goals

1. 为 4 个 bug 给出与现状代码一致的修复方向。
2. 把“已确认根因”和“仍待证据补齐”的部分分开，避免一次修复混入多个未经验证的假设。
3. 明确每个 bug 的最小代码改动面、预期测试入口和回归防护方式。

## Non-Goals

1. 本轮不直接提交修复代码。
2. 本轮不把 `Open` 状态改成 `Verified` 或 `Fixed`。
3. 不对无关 UI、AI、渲染架构做顺手重构。

## Approaches Considered

### Option A - 按 bug 独立修复，逐条补测试（推荐）

- 优点：边界清晰，能把 `BUG-20260315-002` 的“已确认容量问题”和“待确认闪烁问题”拆开处理；每条 bug 都能绑定独立回归测试。
- 缺点：跨模块公共能力（如 UI 文本绘制助手、拖拽事务 helper）需要在多个任务中重复触达。

### Option B - 先做跨模块重构，再回填 bug

- 优点：能一次性统一按钮文本绘制、拖拽事务和 AI 距离配置语义。
- 缺点：改动面过大，难以证明每个 bug 的修复收益，且不符合当前“最小正确改动”的仓库规则。

结论：采用 Option A，以每条 bug 为主线，只在 bug 修复内部抽取必要 helper。

## Bug-by-Bug Design

### BUG-20260315-002 - 掉落丢失 / 闪烁

先拆成两个子问题：

1. `掉落丢失`：修改 `GPULootSystem::SyncDroppedItems` 的顺序，先统计真实 required count，再触发 `EnsureCapacity(required)`，最后写入 GPU upload 缓冲。这样才能让超容量场景真正扩容。
2. `掉落闪烁`：在没有复现证据前，不直接调整 compute barrier。先增加诊断数据（如 `required/synced/visible/maxInstances`）和高掉落量回归入口，确认闪烁究竟来自 upload 截断、可见实例抖动还是后续运动/剔除链路。

预期改动面：`src/engine/render/GPULootSystem.cpp`, `src/engine/render/GPULootSystem.hpp`，必要时补充只读诊断接口供测试使用。

### BUG-20260315-003 - 拖拽换装 / 换包 / 指定格落点

核心是把“拖拽中的源槽”和“目标槽替换”改成显式事务，而不是串联现有 `unequip*` 通用逻辑。

1. 装备路径：在 `equipItem` 替换前先释放拖拽源槽或建立保留槽位，避免 `unequipItem` 因背包被拖拽物仍占用而失败。
2. 扩展包路径：同样把 `equipBag`/`unequipBag` 改成 source-aware 的交换逻辑，避免容量检查把拖拽中的背包继续算作现有占用。
3. 目标槽路径：为“装备 -> 背包指定格”“扩展包 -> 背包指定格”提供显式 API，让 UI 把 hovered slot `i` 传到底层，而不是丢失后回落到首个空槽。

预期改动面：`src/game/systems/item/InventorySystem.cpp`, `src/game/systems/item/InventorySystem.hpp`, `src/game/systems/ui/UIInventory.cpp`。

### BUG-20260315-004 - 按钮 emoji 显示 `?`

统一按钮文本与普通 UI 文本的绘制能力，而不是只给单个按钮打补丁。

1. 让 `UIRenderer::DrawButton` 复用 `DrawTextUI` 的 emoji fallback 路径，或抽出一个共同的按钮文本 helper。
2. 文本测量必须和实际绘制路径一致，否则 fallback 引入后会造成按钮文本居中偏移。
3. 保留 fallback 字体加载失败时的日志与文本降级方案，但不以“删掉 emoji 文案”作为主修复方案。

预期改动面：`src/engine/render/UIRenderer.cpp`，必要时同步 `src/game/systems/ui/UISystem.cpp` 的 fallback 可见性/日志。

### BUG-20260315-005 - 怪物近距离不索敌

把 dormancy 和 aggro 拆成两个有明确语义的距离系统。

1. dormancy：让 `EnemySpawnSystem::updateDormantEntities` 的唤醒距离落入 `AISystem` 的休眠阈值内，或为 freshly-awakened 实体提供短暂免休眠窗口，避免“刚唤醒就再次休眠”。
2. aggro：明确 `activationRange` 与 `detectionRange` 的职责；若两者必须同时存在，就为它们建立统一计算函数/断言/日志，防止配置漂移后实际索敌范围被静默压缩。
3. 修复时要同时覆盖普通怪与 Nemesis，因为两者 dormancy 路径不同。

预期改动面：`src/game/systems/world/EnemySpawnSystem.cpp`, `src/game/systems/ai/AISystem.cpp`, `src/game/components/Common.hpp`，必要时校正 `src/game/components/EnemyComponent.hpp` 默认值说明。

## Verification Strategy

1. 每条 bug 先写失败测试或 tech guard，再做最小修复。
2. `BUG-20260315-002` 先锁定 overflow 扩容，再额外保留手测/诊断流程复核闪烁。
3. `BUG-20260315-003` 重点覆盖满包替换、指定槽落点、双手/副手联动与扩展包替换。
4. `BUG-20260315-004` 既要检查源码是否走 fallback，也要检查按钮文本测量与绘制路径保持一致。
5. `BUG-20260315-005` 要验证“被唤醒后不会立刻再次休眠”以及“近距离目标一定能进入索敌判定”。

## Risks

1. `BUG-20260315-002` 的闪烁根因仍未完全确认，不能把容量修复误报成闪烁修复。
2. `BUG-20260315-003` 涉及 UI 与 InventorySystem 协作，若事务语义没统一，容易只修一条拖拽路径。
3. `BUG-20260315-004` 如果只改绘制不改测量，按钮排版可能发生新回归。
4. `BUG-20260315-005` 如果只调整一个阈值而不补日志/测试，后续配置改动仍可能重新引入压缩 aggro 半径。

## Deliverables

1. 已更新的 `conductor/bug_registry.md`，明确真实根因、计划态解决方案和回归防护。
2. `docs/plans/2026-03-15-bug-20260315-002-005-fix-plan.md`，供后续按任务执行修复。
