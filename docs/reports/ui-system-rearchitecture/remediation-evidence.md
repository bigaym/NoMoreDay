## R3 — 修复 WorldUiFrame 生命周期与 Escape 单一所有者 (2026-08-12)

Status: `done` — findings **H-01** and **H-02 closed**; `Engine GPULootPass` / `RenderGraph` / scene composite untouched; `LabelCacheComponent` render writes stay out of scope (design non-goal).

Evidence:

- **WorldUiFrame per-pass view (design §3.5):** `WorldUiFrame::View` added in `src/game/application/ui/WorldUiFrame.hpp` — binds an expected frame token at acquisition (`AcquireView()` snapshots `m_frameToken`); `View::IsValid()` is `m_frame != nullptr && m_expectedToken != 0 && m_frame->FrameToken() == m_expectedToken`, so a view acquired for a previous pass is rejected even though the frame itself is valid; invalid views expose an empty proxy list / no hover (host treats them as "no world target"). `BeginFrame` itself is unchanged (idempotent, clears proxies + hover, rotates token).
- **BeginFrame before every branch (H-01):** `ExecuteUIWorldPass` in `src/game/application/render/GameplayRenderAdapter.cpp` now runs `m_worldFrame->BeginFrame(++m_frameCounter)` first thing (before the CPU popup text block and the `gpuLootEnabled` early return), so no branch — including the GPU loot path — can expose the previous frame's vector/hover/token.
- **Read-only proxy producer on both paths:** query + cull extracted into `GameplayRenderAdapter::CollectVisibleItemProxies` (read-only: `try_get<LabelCacheComponent>` size only, no `get_or_emplace`, no beams) which fills `WorldUiFrame` proxies for both the `ItemComponent` and `GoldComponent` branches and both the CPU and GPU loot paths; the GPU path skips only the CPU label/glyph/beam output (`BuildCpuLootLabels`), never the proxy fill.
- **Host/tooltip reader gating (H-01):** `GameUiHost::DetectPickupClick` and `TooltipController::DetectGroundHover` acquire a per-frame `WorldUiFrame::View` and return early when `!view.IsValid()`; neither reads a stale frame's proxies. World pickup intents are enqueued only when the current-frame view is valid. Tooltip hover delay (0.12s/0.05s/0.08s) and `dt*10`/`dt*8` tween contract untouched.
- **Escape single owner (design §3.6, H-02):** `GameUiHost::HandleEscape` is the sole UI Escape consumer — closes exactly one topmost surface per the priority chain `quantity popup → character confirm/panel → context menu → skill tree → astrolabe → inventory → stash → crafting` (stash/crafting get an unconditional `Close()`; `UICraftingController::Close()` added). `EscapeConsumedThisFrame()` is reset at the top of every `Update` (before the initialization guard) and set by `HandleEscape`; no surface open → key left unconsumed for gameplay.
- **Pause only on unconsumed Escape edge (H-02):** the `IsInventoryVisible()` pause proxy is gone from `src/game/application/states/GameplayState.cpp`; the new check runs right after `m_uiHost->Update(...)` and pushes `PauseState` only when `IsKeyPressed(KEY_ESCAPE) && !m_uiHost->EscapeConsumedThisFrame()`, so one press is never consumed twice.
- **Tests:** `tests/unit/WorldUiFrameTests.cpp` extended with 4 view/lifecycle cases (AcquireView binds the current token; fresh-frame view invalid until `BeginFrame`; stale view rejected after token rotation — H-01 regression; GPU-branch still fills proxies with monotonic tokens); new `tests/unit/GameUiHostEscapeTests.cpp` (12 cases: per-surface close truth table incl. character-confirm two-step and stash-above-inventory order, exactly-one-topmost priority chain, unconsumed pass-through, per-frame flag reset via `Update` — H-02); new `tests/tech/UiR3RemediationGuardTests.cpp` (4 source guards: `BeginFrame` precedes the `gpuLootEnabled` return, proxy `AddItem` in both branches, host/tooltip gate invalid views before reading, `GameplayState` pause check after `host.Update` and gated by `EscapeConsumedThisFrame` with the old `IsInventoryVisible()` proxy absent).
- **Verification:** `./build.bat novalidate` (RelWithDebInfo) PASS; `ctest --test-dir build -C RelWithDebInfo -L unit` 9/9 PASS; `./bin/NoMoreDayTests.exe --test-case="*WorldUiFrame*,*Escape*,*GameUiHost*,*Tooltip*,*UiPickupFlow*"` 57/57 PASS (391 assertions); full suite 1105/1106 PASS — the single failure is the known pre-existing GPU-environment `[GPU-Diagnostic] RenderGraph - B4 real LightCullingPass contract gate on real GL` (`tests/integration/GraphBindingEquivalenceGLTest.cpp(2100)`, `CHECK_EQ(2,3)`), not attributed to this change; `git diff --check` EXIT=0 (no whitespace errors); `git status --short` change boundary covers only R0-R3 files (R0-R2 changes stacked as expected). ## R4 — 使 runtime/draw-list 成为真实 host 管线 (2026-08-12)

Status: `done` — R4 完成信号达成：message box 作为第一个真实 panel 走完 snapshot→runtime→draw-list→backend 全链且无 immediate fallback（A-01 基础）；C-01 关闭（无 O(n) 有序插入、无每帧 std::string 文本、backend 单趟提交）。A-01 的完全关闭仍依赖 R5-R8 迁移（计划原文：未迁移 panel 不能标记 A-01 完成）。

Evidence:

- **验证 panel 选择（message box）：** 设计文档未指定验证 surface，故选最简 surface——message overlay。理由：单一固定框 + 单行文本，paint 无需 registry，状态经既有 `IsMessageBoxVisible()`/`MessageBoxText()` 可达；context menu / quantity popup 依赖 registry 与 item 交互（归 R6），tooltip 依赖 registry + 多行布局（归 R6/R8）。消息框文本状态经 host 传入（`ShowMessageBox`/`ClearMessageBox` 不变），paint 在 `OverlayController::PaintMessageBox(UiDrawList&, const UiViewport&)` 内以 `Image`（`Button_Frost_Rect` 纹理，`kMessageBoxTextureResourceId`）+ `Text`（`kGlobalFontResourceId`）两条命令产出，nodeId = overlay runtime root。固定 460x60 逻辑框为文档化过渡视觉（legacy 用字体测量贴合文本，需 raylib 于 Draw 层；R6 可经 backend 测量 API 恢复）。
- **Update 变真实管线（设计 §3.1/§3.4）：** `GameUiHost::Update` 现在每帧执行：`UiViewport::Fit`（viewport fit）→ `m_overlay.ReconcileRuntime()`（reconcile：overlay root 可见性 = 消息框可见性）→ 构造 `UiInputFrame{logicalPointer = m_viewport.ToLogical(GetMousePosition()), pressed/released, dt, tooltipTarget}` → `m_runtime.UpdateInput(uiInput)` → `m_runtime.Arrange({0,0,LogicalSize})`。`UiRuntime` 的 input/layout 实现（pointer capture/focus/modal、clip、hit test）为既有合同，R4 不改 UiRuntime 源码，只接通 host 调用（现有 + 新增 host 级测试覆盖其行为）。原 transitional 注释块同步更新。
- **PrepareRender 变真实 paint（设计 §3.1 step 3）：** `PrepareRender()` 保持无参签名（`GameplayState.cpp:1131` 与既有 lifecycle 测试不变），内部为 `m_initialized` guard → `m_drawList.Clear()` → `m_overlay.PaintMessageBox(m_drawList, m_viewport)` → `m_drawList.Finalize()`。旧占位 `Reserve(64)`/空 `Clear` 已删；viewport fit 移至 Update。world hit 不在此阶段执行——`DetectPickupClick` 仅 enqueue 下一帧 intent（既有 R3 契约，R3 已保证无效 view 早退）。
- **Draw/backend 提交（设计 §3.1 step 4）：** `UiRaylibBackend::Render` 单趟遍历已 Finalize 的排序命令（删除旧 `kFirstLayerValue` 每层双层重扫），`DrawCommand` 经 `drawList.TextAt(command)` 读 arena；空列表早退为正确行为保留；debug 守卫断言 `ClipBalanced` 与 `IsFinalized && IsTotalDrawOrder`。raylib 类型仍只出现在 backend 与 host 输入层（`GameUiHost.cpp` 的 `GetMousePosition`/`GetScreenWidth`），controller 层（`OverlayController.cpp`）无 raylib。
- **零分配排序与 text arena（C-01）：** `UiDrawCommand` 的 `std::string text` 删除，改为 `(textOffset, textLength)` 指向 draw-list 的固定容量 text arena（写入时补 `'\0'` 保证 C-string 读不越入上帧残留）；`appendSequence` 使 `(layer, nodeId, appendSequence)` 成为严格总序；`Finalize()` 用 `std::sort` 原位排序（标准保证零分配）。commands/clips/text 容量由 host 在 `Initialize` 期 `Reserve(256)`/`ReserveText(4096)`（新常量 `kUiCommandCapacity`/`kUiTextArenaBytes`），容量经 `CommandCapacity()/ClipCapacity()/TextCapacity()` 可测；溢出（`CommandOverflow()/ClipOverflow()/TextOverflow()`）记录 telemetry 并丢弃/截断，不触发热路径扩容。R0.4 容量来源两行（`GameUiHost.cpp:72` `Reserve(64)` 与旧 `:538` `Reserve(64)`）已变更：runtime `Reserve(64)` 保留，draw-list 占位 reserve 移至 Initialize 的真实容量。
