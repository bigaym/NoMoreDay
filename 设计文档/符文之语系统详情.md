# 符文之语系统设计 (Runeword System)

## 1. 核心理念 (Core Concept)

结合 **Diablo 2** 的经典符文序列机制与 **Titan Quest/Grim Dawn** 的碎片与遗物在底材上的强化思路。

*   **双重价值**：
    *   **独立镶嵌**：每颗符文（Rune）本身就是一种强力的镶嵌物，提供基于底材类型（武器/防具/盾牌）的特定属性。
    *   **符文之语**：当特定符文按**特定顺序**镶嵌在符合孔数要求的**普通（白色/灰色）**底材上时，物品将发生“共鸣”，进化为**符文之语装备**。

*   **与做装系统的交互**：
    *   符文之语装备被视为**独特（Unique）**或**传奇（Legendary）**稀有度。
    *   它们**不能**再进行常规词缀锻造，但可能支持“腐化”或后续的打孔（如果系统允许）。

## 3. 经典符文语示例 (Runeword Examples)

为了致敬 D2 并适应 NoMoreDay 的数值体系，我们复刻并调整部分经典符文语。

### 3.1 隐秘 (Stealth) - 前期神器
*   **序列**：Tal(7) + Eth(5)
*   **底材**：2孔 盔甲
*   **固定属性**：
    *   魔法回复速度 +15%
    *   移动速度 +25%
    *   施法速度 +25%
    *   快速打击恢复 +25%
    *   敏捷 +6
    *   毒素抗性 +30%

### 3.2 精神 (Spirit) - 法系标准
*   **序列**：Tal(7) + Thul(10) + Ort(9) + Amn(11)
*   **底材**：4孔 剑 / 盾牌
*   **固定属性**：
    *   +2 所有技能等级
    *   +25-35% 施法速度 (变量)
    *   +55% 快速打击恢复
    *   +250 对远程防御
    *   +22 活力
    *   (剑) +1-50 电伤, +3-14 冰伤, +75 毒伤
    *   (盾) 冰/电/毒抗性 +35%

### 3.3 悔恨 (Grief) - 近战终极
*   **序列**：Eth(5) + Tir(3) + Lo(28) + Mal(23) + Ral(8)
*   **底材**：5孔 剑/斧
*   **核心机制变化**：D2中的悔恨强在 `Damage +340-400` 直接加在基础伤害上。在 NoMoreDay 的 ItemStats 系统中，我们需要引入 `FLAT_DAMAGE_ADDED` 属性来实现这一点。
*   **固定属性**：
    *   35% 几率施展等级 15 毒液 (Venom)
    *   +30-40% 攻击速度
    *   **伤害 +340-400 (直接附加)**
    *   忽略目标防御
    *   -25% 目标防御
    *   20% 致命一击 (Lo的效果)
    *   防止怪物自疗
    *   +2 击杀回蓝

### 3.4 谜团 (Enigma) - 改变机制
*   **序列**：Jah(31) + Ith(6) + Ber(30)
*   **底材**：3孔 盔甲
*   **特殊能力**：
    *   **+1 传送 (Teleport)** - 允许任何职业使用传送技能。
    *   +2 所有技能
    *   +45% 移动速度
    *   +0.75 力量/每角色等级
    *   物理伤害减免 8%
    *   生命上限 +5%

## 4. 技术实现规格

### 4.1 数据结构
1.  **Runes.json**: 定义单颗符文的属性。`id` 对应 1-33，`effects` 分为 `weapon`, `armor`, `shield` 三组 Affix。
2.  **Runewords.json**: 定义配方。
    ```json
    {
        "id": "rw_spirit_sword",
        "name": "Spirit",
        "runes": ["Tal", "Thul", "Ort", "Amn"],
        "baseTypes": ["Sword"], // 严格限制底材
        "sockets": 4,
        "attributes": [ ... ], // 结果属性
        "isLegacy": true // 标记为传奇/特殊物品
    }
    ```

### 4.2 镶嵌逻辑 (RunewordSystem)
*   监听 `SocketItemEvent`。
*   检查物品是否为 `Rarity::Common` (或者允许灰色底材)。
*   检查当前孔内所有物品的 ID 序列。
*   如果匹配 `Runewords.json` 中的某个序列：
    *   **转化**：修改 `ItemComponent`.`name` (显示为 "Spirit [Broad Sword]")。
    *   **重写**：`ItemComponent`.`rarity` -> `Legendary/Runeword`。
    *   **赋予**：清空原有孔内符文的单独属性（或者保留？D2是保留的），追加符文之语的专属属性列表。
    *   **视觉**：播放特殊的 "Runeword Completed" 特效与音效。

### 4.3 存储与堆叠
*   符文在背包中作为 `ItemType::Material` 或特殊类型 `ItemType::Rune` 存在。
*   支持堆叠 (MaxStack = 100)。
*   可以存入 `MaterialBank`，但必须取出到背包才能进行镶嵌操作。

## 5. 实现风险与待办 (Implementation Risks & TODOs)

在 Phase 2 的初步实现中，识别出以下关键问题，需在后续迭代中解决：

1.  **符文基础属性应用缺失**：
    *   **风险**：目前系统仅在激活符文之语时应用属性，镶嵌单颗符文时未应用其基础 Mod（如 El 符文在武器上的命中加成）。
    *   **对策**：需在 `RunewordSystem` 中实现 `applyRuneStats` 逻辑，根据部位（Weapon/Armor/Shield）动态添加词缀。

2.  **底材匹配粒度不足**：
    *   **风险**：当前底材检查仅基于 `ItemType`（如 Weapon），无法区分 "Staff" 与 "Sword"，可能导致符文语在错误类型的武器上激活。
    *   **对策**：在 `ItemComponent` 中引入 `subType` 或 `Tags` 系统，使 `checkForRuneword` 支持更精细的过滤。

3.  **属性映射表不完整**：
    *   **风险**：`stringToAffixType` 尚未完全覆盖 JSON 中定义的所有属性键值（如 `mana_per_kill`, `light_radius`, `crushing_blow` 等）。
    *   **对策**：补全映射逻辑，确保所有 D2 风格的特殊属性都能正确转换为 ECS 组件数据。

4.  **物品名称不可逆性**：
    *   **风险**：激活符文语时直接覆写了 `item.name`，若未来支持移除符文，将无法找回原始底材名称（如 "Crystal Sword"）。
    *   **对策**：在 `ItemComponent` 中增加 `baseName` 字段持久化保存底材原始名称。
