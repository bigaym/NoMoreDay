# 职业与技能系统设计规范 (Class & Skill System Specification)

战斗口径基线：`设计文档/战斗系统与属性设计.md`（Combat vNext）

## 1. 核心设计理念 (Core Pillars)

### 1.1 标签驱动架构 (Tag-Driven System)

这是游戏构建（Build）系统的基石。所有的技能、装备词缀、天赋节点都通过**标签 (Tags)** 进行关联和计算。

- **解耦**：战斗系统不关心技能的具体名字，只关心它拥有的标签。
- **动态性**：技能的标签可以通过技能专精树改变（例如：将 [物理] 转化为 [火焰] 或 [冰霜]）。

### 1.2 统一法力资源 (Unified Mana Resource)

- 所有职业使用**法力 (Mana)** 作为技能消耗资源，不引入怒气、能量等额外资源条。
- 法力回复由通算属性统一计算：`ManaRegen`（基础值 + 智力 × `INT_TO_MANA_REGEN` + 百分比回复加成）与 `ManaOnHit`（命中返还，单次返还量以缺失法力为上限，且受 `ProcBudgetManager` 的 `ManaOnHit` 预算约束）。不设职业专属回蓝。
- **例外**: 剑修的进阶专精以专属资源替换默认的「剑意 (SwordIntent)」，见 §1.4。

### 1.3 技能互动与触发 (Interaction & Triggers)

- 核心爽点在于技能之间的联动（A 触发 B）。
- 采用**影子施法 (Shadow Casting)** 机制处理触发逻辑。
- 触发收益受 `trigger.effectiveness` 与 `ProcBudgetManager` 双约束。

### 1.4 进阶专精与专精资源 (Mastery)

剑修的进阶专精由 `BladeMasteryId` 与 `BladeResourceKind` 定义，共三系：

| 专精 (BladeMasteryId) | 资源 (BladeResourceKind) | 招牌技能 |
| --- | --- | --- |
| 剑圣 (SwordSaint) | 剑流 (SwordFlow) | 七星斩 (10) |
| 天剑 (HeavenlySword) | 灵剑阶 (SpiritBladeTier) | 天剑降临 (11) |
| 魔剑 (DemonBlade) | 嗜血 (Bloodthirst) | 血海 (12) |

- **解锁**: 各专精 `unlock_level = 50`，调试解锁下限为 5 级（`debug_unlock_level_override`）。
- **资源档案**（`assets/data/blade_masteries.json`）：每系定义 `max_resource = 10`、`grace_period = 5.0s`、`decay_interval = 0.5s`；未选择专精时回退到默认剑意（`DEFAULT_MAX_SWORD_INTENT = 10`、`SWORD_INTENT_GRACE_PERIOD = 5.0`、`SWORD_INTENT_DECAY_INTERVAL = 0.5`）。
- **选择与切换**: `SelectMastery` 校验解锁后写入 `BladeMasteryComponent.selected`；切换时清理其它专精的持久场（技能 12 场、天剑降临场）并刷新资源组件。
- **天剑属性合流 (BladeAttunement)**: 天剑专精额外选择 Lightning / Frost / Fire 之一作为元素倾向。
- **招牌技能**: 选中专精后 `BladeSignatureSkillComponent` 解锁对应 `signature_skill_id`。

## 2. 标签系统定义 (Tag System Definitions)

标签分为两类，用于不同的计算环节。

### 2.1 伤害/元素标签 (Damage Types)

决定伤害的属性计算和抗性结算，例如：

1. **物理 (Physical)**: 基础打击，流血。
2. **火焰 (Fire)**: 燃烧，爆发。
3. **冰霜 (Cold)**: 减速，冻结。
4. **闪电 (Lightning)**: 感电，高频。
5. **暗影 (Shadow)**: 暗影/腐化伤害。
6. **毒素 (Poison)**: 中毒，持续。
7. **虚空 (Void)**: 对应游戏中的腐化/虚空怪物，高伤害但可能有副作用。

伤害标签占据枚举低位（bit 0-6，共 7 种），其位序与 `DamagePool` 的元素槽位一一对应。

### 2.2 机制标签 (Mechanic Tags)

决定哪些加成适用，例如

1. **形态**: 近战 (Melee), 投射物 (Projectile), 范围 (Area), 法术 (Spell), 攻击 (Attack), 位移 (Movement), 剑技 (SwordSkill), 传送 (Teleport), 防御 (Defense), 回旋 (Return), 灵巧 (Dexterity)。
2. **机制**: 命中 (Hit), 暴击 (Critical), 持续伤害 (DamageOverTime), 增益 (Buff), 光环 (Aura), 引导 (Channeled), 次级命中 (SecondaryHit)。
3. **状态**: 流血 (Bleeding), 燃烧 (Burning), 冰冻 (Frozen), 感电 (Shocked), 眩晕 (Stunned), 御剑 (SwordRiding), 精英 (Elite), 首领 (Boss)。

## 3. 职业体系 (Class Archetypes)

采用 **"基础职业 -> 进阶专精"** 的结构。职业由 `ProfessionID` 枚举定义，共六项，在星盘上各占一个 60° 扇区：

| 职业 (ProfessionID) | 定位 |
| --- | --- |
| 剑修 (BladeAscendant) | 御剑而行，以气化形 |
| 秘术师 (Mage) | 掌控元素，毁灭万物 |
| 神官 (Priest) | 神圣治愈，净化心灵 |
| 骑士 (Knight) | 重甲守护，坚不可摧 |
| 游侠 (Ranger) | 百步穿杨，陷阱伏击 |
| 狂战士 (Berserker) | 怒气爆发，愈战愈勇 |

所有职业统一使用法力 (Mana) 作为技能消耗资源，法力回复由 `ManaRegen` 与 `ManaOnHit` 通算属性计算，不设职业专属回蓝（见 §1.2）。

> [!NOTE]
> **职业实施路线规划（2026-09-17 裁定）**：
> 当前阶段严格集中深挖首发职业「剑修 (BladeAscendant)」的 12 技能体系与三大进阶专精（剑圣/天剑/魔剑）的完整纵深，打磨至垂直切片商业级水准；其余 5 个职业（秘术师、神官、骑士、游侠、狂战士）保持枚举与星盘占位，暂不开启其 Build 与技能专精实现。

### 3.1 技能清单 (Skill Roster)

剑修主动技能共 12 个：

1. **流云刺** (1)、**裂空斩** (2)、**灵剑决** (3)、**剑气护体** (4)、**万剑归宗** (5)、**剑阵·诛仙** (6)、**心剑·无影** (7)、**御剑·回旋** (8)、**绝影绝剑** (9)——常规技能，各自携带独立专精树。
2. **七星斩** (10)、**天剑降临** (11)、**血海** (12)——进阶专精招牌技能，专精树与合同由 `assets/data/mastery_skill_trees.json` 承载（见 §5.2）。

## 4. 天赋星盘系统 (The Constellation Board)

采用**同心圆辐射**布局：六个职业扇区各占 60°，公共内环提供通用起点，节点沿半径分层排布。

### 4.1 布局结构

布局与轨道常量由 `AstrolabeConstants.hpp` 定义：

- **职业扇区**: `PROFESSION_COUNT = 6`，`SECTOR_ANGLE = 60°`。
- **轨道半径**: R1 = 150（本命星）、R2 = 300（Tier 1）、R3 = 500（Tier 2）、R4 = 750（Tier 3）。
- **节点尺寸**: 微型/核心节点半径 12，核心天赋半径 16；本命星半径 35。

节点类型由 `TalentNodeType` 定义：**微型节点 (Minor)**、**核心节点 (Major)**、**核心天赋 (Core)**。核心天赋仅主修职业可解锁。

节点按亲和值分层解锁（`TierThreshold`）：

| Tier | 亲和阈值 |
| --- | --- |
| Tier 1 | 0 |
| Tier 2 | 10 |
| Tier 3 | 25 |

- **微型节点**: 炼体术（+10 最大生命值）、聚气诀（+10 最大法力值）、基础剑招（+3 物理伤害）、轻身术（+1 移动速度）、铁壁功（+10 护甲）、淬骨法（+3 力量）、通感术（+3 敏捷）、明心诀（+3 智力）、吐纳法（+5 生命回复）。

- **微型节点**: 流云剑法（+2% 攻击速度）、弱点洞察（+1% 暴击率）、元素剑气（+5% 元素伤害）、幻影身法（+1% 闪避率）、剑气护盾（+1% 格挡率）、神识锁定（+20 命中值）、灵力扩充（+5% 法力上限）、玄武之壳（+5% 护甲）、青龙之息（+5% 生命回复）、御剑术（+5% 投射物速度）、剑气回响（+5% 范围效果）、灵力反馈（+2 击中回蓝）、剑意留影（+2% 暴击率）、御剑乘风（+2% 移动速度）、剑意护体（+1% 全局减伤）、长生之魂（+5% 最大生命）。

## 5. 技能与专精系统 (Skills & Specialization)

### 5.1 技能槽位

- 玩家拥有 **5个主动技能槽位** (Q, W, E, R, RMB)。
- 必须在有限的槽位中通过搭配实现最大化收益。

### 5.2 技能专精树 (Skill Spec Tree)

每个主动技能都有独立的技能树，节点规模为 25-29 个：1-9 号常规技能为 28-29 个节点，进阶专精招牌技能 10-12 号分别为 26/25/25 个。玩家通过使用该技能升级来获得专精点数；每个技能的专精点数上限为 `DEFAULT_MAX_TALENT_POINTS = 20`，装备可额外提供 `bonus_levels`，分配与退回由 `SkillSystem` 维护 `ActiveSkillsComponent.available_talent_points`。

技能数据分两处承载：1-9 号技能的专精树（`talent_tree`）与节点合同（`skill_contract`）随 `assets/data/skills.json` 定义；10-12 号招牌技能的基础定义（`mana_cost` / `cooldown` / `base_damage` / `params`）在 `skills.json`，专精树与合同在 `assets/data/mastery_skill_trees.json`。

#### 节点类型：

节点角色由 `SpecNodeRole` 定义：

1. **被动 (Passive)**: 数值增强，增加伤害、减少冷却、增加范围。
2. **转质 (Transmuter)**: 改变技能标签并转换伤害元素。同一技能由合同 `max_transmuters` 限制生效数量，候选节点由 `transmuter_node_ids` 声明，同一时刻仅有激活的转质节点生效。
3. **触发 (Trigger)**: 命中或暴击时触发另一技能，由 `TriggerContract` 定义 `trigger_skill_id`、`effectiveness`、`internal_cooldown`、`base_chance`、`requires_crit`、`requires_melee_hit` 与 `required_window` 等约束。
4. **协同 (Synergy)**: 与其它技能或状态联动的节点。
5. **关键 (Keystone)**: 由 `keystone_exclusion_group` 分组互斥的关键节点。

#### 节点点数与机制数值读点

- 节点点数唯一读点：`skills::ReadPoints` / `skills::HasNode`（`SkillPointAccess.hpp`），行为与 UI 层禁止直接访问 `SpecializedSkill.allocated_points`。
- 节点机制数值唯一来源：`assets/data/skill_mechanics.json`（`SkillMechanicsRegistry`），以 `(skill_id, node_id, key)` 三元组经 `skills::GetMech` 读取，缺失键回退默认值；键名漂移由可选 `skill_mechanics_schema.json` 在加载期校验。

#### SpecState 生成流程

1. `assets/data/skill_specstate/<skill>.json` 描述「节点 id → 标识符」。
2. `scripts/gen_skill_contracts.py` 依据专精树拓扑、`skill_contracts_compact.json` 与 `skill_mechanics.json`，生成 `behaviors/generated/<Skill>SpecState.gen.hpp`（POD 状态 + 点数/标记绑定表）。
3. 运行时 `ResolveSpecState` 读取 `ActiveSkillsComponent.specialized_slots` 中匹配 `skill_id` 的分配，先填充点数绑定、再填充标记绑定。

### 5.3 触发机制规范 (Interaction Rules)

为了防止无限循环和性能崩溃，必须遵守以下 vNext 规则：

1. **影子施法 (Shadow Casting)**:
- 触发技能由影子路径执行，通常不消耗法力，不播放完整前摇。

2. **深度限制 (Depth Limit)**:
- 默认只允许 A 触发 B，触发深度上限为 1。
- 若设计需要深度 2，必须显式声明并通过发布门禁评审。

3. **效率缩放 (Effectiveness)**:
- 每个触发节点必须声明 `trigger.effectiveness`。
- 触发伤害按 `TriggerEff` 进入统一伤害公式，不再使用隐式硬编码倍率。

4. **预算治理 (Proc Budget)**:
- 触发、击回、异常施加、事件发射均受预算限制。
- 预算耗尽时限流或降采样，禁止“超预算强行放行”。

5. **修饰继承**:
- 被触发技能保留自身专精树效果。
- 触发源对被触发技能的附加修正必须显式合同化。

### 5.4 元素路径 (Element Path)

御剑·回旋（技能 8）的飞剑轨迹在飞行途中留下元素残留，由 `ElementPathSystem` 管理：

- **数据结构**: 路径段以定长数组挂在归属实体的 `ElementPathComponent` 上（零堆分配），同类元素路径取并集；单 owner 最多 `kMaxSegmentsPerOwner = 32` 段，超出后淘汰最旧段。
- **`PathSegment`（POD）**: `start`、`end`、`half_width`、`duration`、`remaining`、`amp`、`penetration`、`arc_freq_mult`、`arc_timer`、`vfx_timer`、`cast_id`、`skill_id`、`active`。
- **节点**:
    1. **870 劫灰路径 / 872 电磁回旋**: 飞剑轨迹在地面留下火焰/电弧残留（`element_tag` 取 `Tag::Fire` / `Tag::Lightning`）。
    2. **871 燎原之势**: 路径内对应元素增伤（写入 `amp`）。
    3. **873 高压电弧**: 按 `arc_freq_mult` 沿路径索敌放电。
    4. **875 灵根破壁**: 依赖路径判定提供该次攻击的元素穿透（写入 `penetration`）。
    5. **876 元素护体**: 施法者站在自身路径上时提供对应元素绝对减伤。
- **抗性修正挂点**: 位于 `DamageMitigationService`（combat 域），本系统只负责路径事实与电弧伤害。

## 6. 伤害计算管道 (Damage Calculation Pipeline)

vNext 采用“单入口 + 合同化”流水线。所有技能、触发、召唤、DoT 必须共用该路径。

### 6.1 技能基础属性 (Base Skill Stats)

技能定义至少包含以下字段：

1. `Flat Skill Damage`（技能基础点伤）
2. `Weapon Damage %`（武器伤害占比）
3. `added_damage_effectiveness`（附加点伤效率）
4. `trigger.effectiveness`（触发效率，触发节点必填）
5. 语义标签（`Hit` / `DamageOverTime` 为标签；Ailment 与 Summon 为合同类别，不占用标签位）
6. 触发约束（ICD、深度、预算影响）

### 6.2 统一公式与步骤

伤害按**逐元素实例**分段结算，落点为 `DamagePipeline::Calculate`。每个实例：

```text
Instance = Base × (1 + Increased) × Π More × TriggerEff × EndgameMore × CritMult
FinalDamage = (Σ Instance 经防御结算) × Π 后置乘区
```

执行顺序：

1. 前置拦截：无敌判定（`EvaluateInvulnerability`）命中则清零；`SuppressorComponent` 按距离施加减伤。
2. 构建基础池 `DamagePool`（按伤害元素位索引，容量 16），并归一附加点伤效率：`added_effectiveness = request.added_effectiveness × SkillData::added_damage_effectiveness`。
3. 处理转换与额外获得（`ModifierType::Convert` / `GainExtra`）：`Convert` 总和超过 100% 时按比例缩放，`GainExtra` 不封顶且不扣减源元素。
4. 逐实例乘区：
    1. 暗影分身缩放（`ShadowComponent::damage_scale` 或分身常量）。
    2. `Increased`：`StatsSystem::GetStatWithTags` 按属性类型与实例标签取值（百分比制，100 为基准），并叠加载荷 `increased_damage`。
    3. `More`：条件 More、载荷 More、全局修饰器、专精节点（`(1 + value/100)^points`）、代价词缀与 `SkillModifierComponent` 经 `MoreAccumulator` 按来源标签连乘。
    4. 终局 More（`endgame.outgoing_damage_more`）。
    5. `TriggerEff`：由施法来源的触发效力与请求字段相乘。
5. 暴击结算：仅 `Hit` 且非 `DamageOverTime` 参与；暴击倍率按「快照 → 载荷 → 实时属性」优先级取值，模拟路径取期望值 `1 + chance × (mult − 1)`。
6. 防御合同：`DamageMitigationService::Apply`（闪避 / 格挡 / 护甲 / 抗性 / 全局减伤 / 屏障 / 生命）；`BladeWardComponent` 可在结算后拦截并将伤害清零。
7. 后置乘区：`Suppressor`、以攻代守、凛冬附魔等整体缩放 `total_damage` 与 `final_pool`，维持 `total_damage == Σ final_pool` 守恒。
8. 事件派发：伤害事件载荷携带最终承伤值 `final_applied_damage` 与实际元素标签。

语义约束：

1. DoT 必须带 `Tag::DamageOverTime` 且必须实际扣血。
2. Hit 不得冒充 DoT，DoT 不得吃 Hit 专属收益。
3. 事件载荷必须反映最终承伤值（`final_applied_damage`）。

### 6.3 示例（触发效率与附加效率）

技能 A（主技能）触发技能 B（影子施法）时：

1. A 按自身 `added_damage_effectiveness` 计算本体伤害。
2. B 的伤害先按 B 的 `added_damage_effectiveness` 计算基础池。
3. B 最终结果再乘以触发节点的 `trigger.effectiveness`。
4. 若预算不足，B 可被限流；未执行则不应产生命中收益事件。

## 7. 新增内容的契约校验 (Contract Validation)

新增职业或技能时必须满足以下机制约束：

1. `python scripts/gen_skill_contracts.py` 生成 `skill_contract` 并通过 `--check` 漂移校验。
2. 触发链深度、预算与 `trigger.effectiveness` 参数完整。
3. 四流派（直伤 / DoT / 召唤 / 触发）回归通过。

## 8. UMR 修饰执行约束

职业技能专精和星盘天赋的数值修饰统一由统一修饰器运行时系统 `UMR` 执行：`设计文档/统一修饰器运行时系统_UMR.md`。

约束如下：

1. 不再在适配器中写死节点 id、倍率或平铺值常量。
2. 节点效果通过 `modifier_v2` 数据定义，并由 runtime record 过滤后执行。
3. 新增专精/天赋节点时，必须同步补齐：
   - `assets/data/modifier_v2/skill_spec_modifiers.json` 或 `talent_modifiers.json`
   - 对应单元测试（至少覆盖一个正例和一个过滤失配反例）
