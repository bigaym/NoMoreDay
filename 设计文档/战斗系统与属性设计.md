# 2D 暗黑Like Roguelite RPG - 战斗系统与属性设计 V0.2

## 1. 设计哲学 (Design Philosophy)

- **数据驱动 (Data-Driven)**：所有战斗计算依赖于 `CombatStats` 组件，而非硬编码在函数中。
- **烘焙机制 (Baking)**：`StatsSystem` 负责将复杂的来源（基础属性、装备、Buff、天赋）每帧“烘焙”成最终的扁平化数据。战斗逻辑只读取这个最终结果，不关心来源。
- **快照机制 (Snapshotting)**：投射物（Projectile）在生成时应复制施法者的当前 `CombatStats` 快照，确保伤害计算的一致性。

## 2. 属性体系 (Attribute System)

### 2.1 基础属性 (Primary Stats)

基础属性是角色的“基因”，决定了角色的成长倾向。

| 属性 | 英文 | 缩写 | 影响 (每点) | 适用职业 |
| :--- | :--- | :--- | :--- | :--- |
| **力量** | Strength | STR | +1% 物理伤害, +5 护甲 | 战士, 圣教军 |
| **敏捷** | Dexterity | DEX | +0.1% 暴击率, +0.1% 闪避率, +1% 攻速 | 游侠, 刺客 |
| **智力** | Intelligence | INT | +1% 元素伤害, +0.5 全抗性, +2 最大法力, +1% 护盾维持 | 法师, 术士 |
| **体能** | Vitality | VIT | +10 最大生命值, +0.2 生命回复 | 所有职业 |

### 2.2 战斗属性 (Combat Stats) - 最终面板

这是 `StatsSystem` 计算后的产物，也是 UI 面板直接显示的数据。

#### 核心层 (Core Layer)
- **Health / MaxHealth**: 生命值。
- **Mana / MaxMana**: 资源池。
- **Barrier** (New): 护盾值 (混合了 PoE Energy Shield 和 LE Ward 的机制)。
- **Movement Speed**: 移动速度 (px/sec)。

#### 进攻层 (Offensive Layer)
- **Weapon Damage**: `[Min, Max]` 基础区间。
- **Flat Damage**: 附加点伤（数组，对应 6 种伤害类型）。
- **Multipliers**: 伤害类型加成（数组，对应 6 种伤害类型）。
- **Crit**: 暴击率 (Chance) 与 暴击伤害 (Damage)。
- **Speed**: 攻击速度 (Attack Speed) 与 施法速度 (Cast Speed)。

#### 防御层 (Defensive Layer)
- **Armor**: 物理减伤。
- **Resistances**: 元素减伤（数组，对应 6 种类型）。
- **Dodge**: 闪避率（完全规避伤害）。
- **Block**: 格挡率（减免部分伤害）。

## 3. 战斗公式 (Combat Formulas)

### 3.1 伤害计算流水线 (Damage Pipeline)

$$
FinalDamage = (BaseWeapon + FlatBonus) \times (1 + \sum Increases) \times (1 + \sum Mores) \times CritMult \times Mitigation
$$

1.  **基础伤害 (Base)**: `Random(MinWeapon, MaxWeapon) + FlatDamage[Type]`
2.  **增伤 (Multipliers)**: `Damage * DamageMultipliers[Type]`
3.  **暴击 (Crit)**: `if (Random(0,1) < CritChance) Damage *= CritDamage`
4.  **防御 (Mitigation)**:
    - **物理**: `Damage *= (1 - Armor / (Armor + 50 * AttackerLevel))`
    - **元素**: `Damage *= (1 - clamp(Resistance, -1.0, 0.75))` (抗性上限 75%)

### 3.2 护甲公式建议

建议使用非线性公式，避免堆叠护甲收益过高或过低：
$$
DR = \frac{Armor}{Armor + K \times Level}
$$
其中 $K=50$ 是常数。这意味着同级怪物攻击下，护甲值等于 $50 \times Level$ 时提供 50% 减伤。

## 5. 进阶设计建议 (Advanced Suggestions)

### 5.1 技能标签系统 (Tag System)
为了让属性系统生效，技能必须拥有标签。
- 例如：**火球术** 拥有 `[Spell, Fire, Projectile, AoE]` 标签。
- 属性加成逻辑：
  - `Intelligence` -> 增加 `Spell` 伤害。
  - `Fire Damage %` -> 增加 `Fire` 伤害。
  - `Cast Speed` -> 减少 `Spell` 施法前摇。

### 5.2 击回与吸血 (Recovery)
- **Life on Hit (击回)**: 适合高攻速、低单发伤害的 BD (Build)。
- **Life Leech (吸血)**: 适合高爆发 BD。建议设定“吸血上限 (Leech Cap)”，例如每秒最多回复 20% 最大生命值，防止瞬间回满。

### 5.3 投射物快照 (Projectile Snapshotting)
当玩家发射火球时，火球的伤害数据应包含玩家**发射瞬间**的属性。
- 如果玩家发射后喝了药水（增加伤害），**已飞行在空中的火球**伤害不应改变。
- 实现：`ProjectileComponent` 中应包含一个 `SnapshotStats` 结构体，而不是引用玩家实体。

## 6. 护盾与防御机制 (Barrier & Defense Mechanics) [NEW]

我们采用 **"混合护盾 (Hybrid Barrier)"** 机制，旨在兼容 PoE 的充能护盾和 LE 的衰减护盾。

### 6.1 核心属性

| 属性名 (Stat) | 默认值 | 说明 |
| :--- | :--- | :--- |
| **Barrier** | 0 | 当前护盾值。优先于生命值扣除。 |
| **Max Barrier** | 0 | 护盾上限 (Soft Cap)。衰减机制以此为基准。 |
| **Barrier Regen** | 0 | 每秒自动回复量 (ES Style)。 |
| **Barrier Decay** | 0% | 每秒衰减当前护盾的百分比 (Ward Style)。通常为 20%/s。 |
| **Barrier Delay** | 2.0s | 受伤后暂停回复的时间。 |
| **Barrier Retention** | 100% | 降低 Decay 的速率。`RealDecay = BaseDecay / (1 + Retention)`。 |

### 6.2 运作逻辑

1.  **承伤顺序**: 伤害 -> 护盾 -> 血量。
    *   *例外*: **Chaos/True Damage** 穿透护盾直接扣血 (除非有 `Shavronne's Wrappings` 类似词缀)。
2.  **衰减模式 (Ward Mode)**:
    *   当 `CurrentBarrier > MaxBarrier` 时，护盾会自然衰减。
    *   公式: `DecayAmount = (Current - Max) * (0.2 / (1 + Retention))`。
    *   适用于: 临时获得的护盾 (e.g. "击中获得 10 护盾")。
3.  **充能模式 (ES Mode)**:
    *   当 `CurrentBarrier < MaxBarrier` 且 `LastDamageTime > BarrierDelay` 时，护盾开始回复。
    *   公式: `RegenAmount = MaxBarrier * RegenPct + FlatRegen`。
    *   适用于: 法师/护盾流派的常驻防御。

### 6.3 交互范例

- **流派 A (纯护盾流)**:
  - 堆高 `Max Barrier` 和 `Int` (提供 %ES)。
  - 依靠 `Barrier Regen` 回复。
  - 弱点: 持续伤害打断回复。

- **流派 B (狂战士流)**:
  - `Max Barrier` 极低 (0)。
  - 装备词缀: "击中获得 50 护盾 (Gain Ward on Hit)"。
  - 通过高攻速维持一个动态的护盾池，一旦停手护盾迅速衰减。
