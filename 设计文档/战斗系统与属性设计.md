# 战斗系统与属性设计 V1.0（Combat vNext 基线）

权威来源：

- `src/game/systems/combat/`（伤害结算与防御减免实现）
- `src/game/contracts/`（战斗事件、伤害请求与预算合同）
- `src/game/foundation/data/`（技能数据与专精节点合同）
- `设计文档/核心战斗与角色设计.md`
- `设计文档/职业被动和技能设置.md`
- `设计文档/怪物和AI设计.md`

> 本文为战斗实现的合同基准，实现、调参与测试以本文为准。

## 1. 核心原则

1. 唯一数值入口：所有 Hit/DoT/Trigger/Summon 伤害必须经 `DamagePipeline`。
2. 语义清晰：Hit、DoT、Ailment 三类语义互斥并可追踪。
3. 事件可信：战斗事件载荷必须与实际承伤一致。
4. 预算治理：高频触发、击回与事件派发受 `ProcBudgetManager` 限流。
5. 召唤合同化：召唤伤害统一三元归因（`owner/summon/source_skill`）。

## 2. 战斗执行链（帧序合同）

必须保持以下顺序：

`Input -> Player Movement -> AI -> Combat -> Spatial Grid Rebuild -> Physics -> Render`

其中 Combat 阶段内部按统一口径执行：

1. 技能/效果系统提交伤害上下文（`DamageRequest`）。
2. `DamagePipeline::Calculate` 计算最终承伤值；`dispatch_damage_events=true` 时在其末尾直接派发伤害事件。
3. `DamagePipeline::Execute` 以 `dispatch_damage_events=false` 调用 `Calculate`，再经 `CombatSystem::ApplyDamage` 落地生命/屏障变更。
4. `Execute` 在 `dispatch_damage_events=true` 时以最终承伤值派发一次事件；`is_simulation=true` 或命中被闪避时不落地、不派发。

## 3. 属性与面板

`StatsSystem` 负责来源烘焙，输出战斗只读面板。核心字段如下：

1. 资源层：`Health/MaxHealth`、`Mana/MaxMana`、`Barrier/MaxBarrier`。
2. 进攻层：`WeaponDamage`、`AddedDamage`、`Increased/More`、`Crit`、`Speed`。
3. 防御层：`Dodge`、`Block`、`Armor`、`Resistance`、`GlobalDamageReduction`。
4. 机制层不进入 `CombatStats` 面板，分处三处结构：
   - `SkillData.added_damage_effectiveness`、`DamageRequest.added_effectiveness`（`foundation/data/SkillRegistry.hpp`、`contracts/DamagePipelineTypes.hpp`），两者相乘得到实际 `AddedEff`。
   - `NodeContractData.trigger.effectiveness`、`SkillExecution.trigger_effectiveness`（`foundation/data/SkillContract.hpp`），两者相乘得到实际 `TriggerEff`。
   - `ProcBudgetConfig`（`contracts/impl/ProcBudgetManager.hpp`）提供各预算维度的默认值与上限。

## 4. 伤害合同（Damage Contract）

结算按分段顺序执行：

1. 基数与点伤：每个伤害实例以武器/技能配置点伤或 `(base_damage_min + base_damage_max) * 0.5` 为基数，`CombatStats.flat_damage[element] * AddedEff` 作为独立实例累加。
2. `(1 + Increased)`：`damage_percent_add` 按元素求和后乘算。
3. `More`：`damage_percent_mult_component`、词缀、专精节点按标签聚合为乘积 `final_more`，逐实例乘算。
4. `TriggerEff`：`inst.amount *= trigger_effectiveness`。
5. 暴击：`Hit` 且非 `DamageOverTime` 实例按暴击几率与暴击倍率乘算，含条件暴击倍率增量。
6. `Mitigation`：由 `DamageMitigationService::Apply` 按防御合同顺序结算。
7. 终局乘区：`suppressor_multiplier`、`endgameDamageMoreMultiplier`、一次性全局 More 标记、凛冬附魔增伤等逐项乘算。

字段约束：

1. `AddedEff` = `DamageRequest.added_effectiveness`（下限 0）× `SkillData.added_damage_effectiveness`
2. `TriggerEff` = `DamageRequest.trigger_effectiveness`（下限 0）× `SkillSystem::GetTriggerEffectivenessForCast(cast_id)`；无施法 id 时回退 `SkillExecution.trigger_effectiveness`
3. `Mitigation` 由防御合同统一提供
4. DoT 路径必须执行“Calculate + ApplyDamage”闭环，禁止“只计算不扣血”

## 5. 语义合同（Hit / DoT / Ailment）

1. Hit：
- 必含 `Tag::Hit`
- 不得含 `Tag::DamageOverTime`

2. DoT：
- 必含 `Tag::DamageOverTime`
- 不进入 Hit 专属收益分支

3. Ailment：
- 统一由 `AilmentEngine v1` 管理叠层、刷新、覆盖、免疫、tick 策略

4. `Tag::Hit` 由投递方在 `DamageRequest.additional_tags` 中显式置入（`ProjectileSystem`、`SummonCombatBridge`、`ElementPathSystem`、`behaviors/*` 等投递点）；`DamagePipeline` 不做集中强制校验，仅在暴击与 Hit 专属收益分支按 `HasTag(tags, Tag::Hit)` 判定。

## 6. 防御合同（Defense Contract v1）

固定结算顺序：

1. 命中与闪避判定
2. 格挡判定
3. 护甲/抗性减免
4. 全局减伤与特殊减伤
5. 屏障吸收
6. 生命结算与死亡判定

要求：

1. 顺序唯一且实现唯一
2. 调试日志可按步骤追踪

实现分布：

1. 命中/闪避与格挡判定：`DamagePipeline.cpp` 的 `ResolveDefenseResolution`。
2. 格挡倍率、护甲/抗性减免、全局与特殊减伤：`DamageMitigationService::Apply`。
3. 屏障吸收、生命结算与死亡判定：`CombatSystem::ApplyDamage`。

## 7. 事件合同（Event Contract）

`CalculateBatch` 与单体路径均必须使用最终承伤值发事件。事件载荷最小字段：

1. `reported_damage`
2. `final_applied_damage`
3. `damage_tags`
4. `owner/summon/source_skill`（召唤事件必填）

目标：事件值与实际承伤一致率 `>= 99.9%`。

## 8. 召唤合同（Summon Contract）

1. 召唤伤害不得绕过 `DamagePipeline` 直接改生命。
2. 三元归因强制：`owner`（收益归属）、`summon`（执行体）、`source_skill`（来源技能）。
3. 继承模式支持：`Dynamic`、`Snapshot`、`Mixed`。
4. 召唤路径受同一套 Trigger/Proc 预算约束。

## 9. Proc 预算合同（ProcBudget v1）

统一预算维度：

1. `life_on_hit_per_sec`
2. `mana_on_hit_per_sec`
3. `ailment_proc_per_sec`
4. `trigger_proc_per_sec`
5. `event_emit_per_frame`

执行规则：

1. 先扣预算再触发收益
2. 超预算时按策略限流/降采样，禁止无限放大

## 10. 发布门禁与验收指标

核心门禁：

1. 合同校验：`python scripts/gen_skill_contracts.py --check` 持续通过
2. 正确性：DoT 生效率、事件一致率、触发越界率达标
3. 性能：战斗帧时间 p95/p99 达到发布阈值
4. 稳定性：高压场景无预算失控与回归爆炸

## 11. 文档维护规则

1. 新增技能机制或伤害路径时，先改合同再改实现。
2. 若实现与本文冲突，以“修实现”为默认，不得只改文档绕过。
3. 与终局/Boss 联动时，同步更新：
- `设计文档/局外成长与终局玩法.md`
- `设计文档/怪物和AI设计.md`
- `设计文档/职业被动和技能设置.md`
