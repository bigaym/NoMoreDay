# 战斗系统与属性设计 V1.0（Combat vNext 基线）

最后更新：2026-02-25  
适用版本：Combat System vNext（M1-M3 已完成）  
权威来源：

- `conductor/analyzer/combat_system_review.md`
- `conductor/analyzer/combat_system_improvement_plan.md`
- `conductor/analyzer/combat_system_capability_roadmap.md`
- `conductor/tracks.md`（`combat_*_20260225` 归档状态）

> 本文替代旧版 V0.2 口径。后续实现、调参与测试必须以本文合同为准。

## 1. 核心原则

1. 唯一数值入口：所有 Hit/DoT/Trigger/Summon 伤害必须经 `DamagePipeline`。
2. 语义清晰：Hit、DoT、Ailment 三类语义互斥并可追踪。
3. 事件可信：战斗事件载荷必须与实际承伤一致。
4. 预算治理：高频触发、击回与事件派发受 `ProcBudgetManager` 限流。
5. 召唤合同化：召唤伤害统一三元归因（`owner/summon/source_skill`）。

## 2. 战斗执行链（帧序合同）

必须保持以下顺序：

`Input -> Player Movement -> AI -> Combat -> Spatial Grid Rebuild -> Physics -> Render`

其中 Combat 阶段内部按统一口径执行：

1. 技能/效果系统提交伤害上下文。
2. `DamagePipeline` 计算最终承伤值。
3. `CombatSystem::ApplyDamage` 落地生命/屏障变更。
4. `CombatEventDispatcher` 发出一致性事件。

## 3. 属性与面板

`StatsSystem` 继续负责来源烘焙，输出战斗只读面板。核心字段如下：

1. 资源层：`Health/MaxHealth`、`Mana/MaxMana`、`Barrier/MaxBarrier`。
2. 进攻层：`WeaponDamage`、`AddedDamage`、`Increased/More`、`Crit`、`Speed`。
3. 防御层：`Dodge`、`Block`、`Armor`、`Resistance`、`GlobalDamageReduction`。
4. 机制层：`added_damage_effectiveness`、`trigger.effectiveness`、预算参数。

## 4. 伤害合同（Damage Contract）

统一基式：

```text
FinalDamage = ((Base + Added * AddedEff) * (1 + Increased) * More * TriggerEff) * Mitigation
```

字段约束：

1. `AddedEff` = `SkillData.added_damage_effectiveness`
2. `TriggerEff` = `NodeContractData.trigger.effectiveness`
3. `Mitigation` 由防御合同统一提供
4. DoT 路径必须执行“Calculate + ApplyDamage”闭环，禁止“只计算不扣血”

## 5. 语义合同（Hit / DoT / Ailment）

1. Hit：
- 必含 `Tag::Hit`
- 不得含 `Tag::DamageOverTime`

2. DoT：
- 必含 `Tag::DamageOverTime`
- 不进入 Hit 专属收益分支

3. Ailment：
- 统一由 `AilmentEngine v1` 管理叠层、刷新、覆盖、免疫、tick 策略

## 6. 防御合同（Defense Contract v1）

固定结算顺序：

1. 命中与闪避判定
2. 格挡判定
3. 护甲/抗性减免
4. 全局减伤与特殊减伤
5. 屏障吸收
6. 生命结算与死亡判定

要求：

1. 顺序唯一且实现唯一
2. 调试日志可按步骤追踪

## 7. 事件合同（Event Contract）

`CalculateBatch` 与单体路径均必须使用最终承伤值发事件。事件载荷最小字段：

1. `reported_damage`
2. `final_applied_damage`
3. `damage_tags`
4. `owner/summon/source_skill`（召唤事件必填）

目标：事件值与实际承伤一致率 `>= 99.9%`。

## 8. 召唤合同（Summon Contract）

1. 召唤伤害不得绕过 `DamagePipeline` 直接改生命。
2. 三元归因强制：`owner`（收益归属）、`summon`（执行体）、`source_skill`（来源技能）。
3. 继承模式支持：`Dynamic`、`Snapshot`、`Mixed`。
4. 召唤路径受同一套 Trigger/Proc 预算约束。

## 9. Proc 预算合同（ProcBudget v1）

统一预算维度：

1. `life_on_hit_per_sec`
2. `mana_on_hit_per_sec`
3. `ailment_proc_per_sec`
4. `trigger_proc_per_sec`
5. `event_emit_per_frame`

执行规则：

1. 先扣预算再触发收益
2. 超预算时按策略限流/降采样，禁止无限放大

## 10. 发布门禁与验收指标

核心门禁：

1. 合同校验：`python scripts/gen_skill_contracts.py --check` 持续通过
2. 正确性：DoT 生效率、事件一致率、触发越界率达标
3. 性能：战斗帧时间 p95/p99 达到发布阈值
4. 稳定性：高压场景无预算失控与回归爆炸

参考门禁套件：`combat_release_gate_suite_20260225`（已归档）。
