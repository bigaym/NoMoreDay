# 2D 暗黑Like Roguelite RPG - 地图与敌人系统设计 V0.5

## 1. 地图生成系统 (Map Generation System)

### 1.1 设计目标

- **高可玩面积**：避免由于随机生成导致的死胡同过多或地形破碎。
- **探索感**：配合战争迷雾，引导玩家探索。
- **一次性体验**：玩家通过传送门离开后，当前地图立即销毁。

### 1.2 核心算法：分样式细胞自动机 (Style-based Cellular Automata)

`MapSystem::generateMap` 根据 `BiomeConfig::style` 分发：`Town` 样式走 `generateTownMap`（仅边界墙 + 出生点/出口），其余样式由 `BiomeMapGenerator::GenerateForBiome` 处理。`BiomeMapGenerator::CreateStrategy` 按样式选择生成策略：

| BiomeStyle | 策略类 | wallProbability 钳制区间 | smoothIterations 下限 |
| :--- | :--- | :--- | :--- |
| `Town` / `Open` | `OpenBiomeStrategy` | [0.05, 0.70] | 1 |
| `Maze` | `MazeBiomeStrategy` | [0.25, 0.80] | 3 |
| `Special` | `SpecialBiomeStrategy` | [0.20, 0.75] | 2 |

生成流程为：`GenerateTerrain`（初始化随机墙 + 双缓冲 CA 平滑 + 边界处理）→ `PlaceSpecialStructures`（样式专属结构）→ `EnsureConnectivity` → `PlaceExits` → `ApplyFeatures`。非城镇地图尺寸为 500x500 瓦片，城镇地图尺寸为 128x128 瓦片。

CA 判定使用 `wallBirthLimit`（默认 4）与 `wallDeathLimit`（默认 3）：墙格邻居墙数小于 `wallDeathLimit` 转为地板，地板格邻居墙数大于 `wallBirthLimit` 转为墙，边界每轮强制重置为墙。

 1. **初始化**：每个格子按 `wallProbability` 判定为墙，其余为地板。
 2. **平滑迭代 (Smoothing)**：遍历每个格子统计八邻域墙壁数量并按上下限更新，重复 `smoothIterations` 次，形成自然的洞穴状地形。
 3. **连通性检查 (Connectivity)**：使用泛洪算法标记最大的连通区域（主区域），剔除所有不与主区域相连的小空洞，确保地图连通性。
 4. **边界处理**：强制将地图最外圈设为不可破坏的墙壁。
 5. **样式结构**：`MazeBiomeStrategy` 额外开挖走廊（数量 `max(8, 面积/1800)`，宽 2~3，步长 10~30）并处理死胡同（35% 概率清除）；`SpecialBiomeStrategy` 按 `numericId` 生成浮空平台/桥梁（`FloatingIsle`、`SkyPalace`）、神圣竞技场（`HolyArena`）或巢穴腔室（`HiveNest`）。

`CaveMapGenerator` 为独立的洞穴生成器（初始墙率 `INITIAL_WALL_PROB = 0.05`、岩石生长、连通性检查、出口放置，`START_SEARCH_RADIUS = 20`、`EXIT_ATTEMPTS = 1000`），由 `MapSystem::generateCaveMap` 调用。

### 1.3 战争迷雾 (Fog of War)

通过 `FogOfWarSystem` 系统管理迷雾状态，与 `MapSystem` 集成，支持三态迷雾（未探索、已探索、当前可见）。

 采用经典的三态迷雾系统：

 - **未探索 (Unexplored)**：全黑，不渲染地形和单位。
 - **已探索 (Explored)**：灰色半透明，渲染静态地形，但不更新或渲染动态单位（敌人）。
 - **当前可见 (Visible)**：全亮，渲染所有内容。

 **更新逻辑**：
 玩家移动时，实时计算视野半径内的格子状态。上一帧可见但当前不在视野内的区域降级为"已探索"。

### 1.4 视觉构建：自动图块拼接 (Auto-Tiling)

当前使用简单的颜色渲染，但代码结构支持纹理贴图。`MapSystem::render` 方法中根据瓦片类型渲染不同颜色，可以扩展为使用自动图块拼接技术。

 为了消除"棋盘格"的生硬感，使用 **Bitmasking** 技术。

 - **原理**：检查当前墙壁周围方向的邻居状态，生成掩码值。
 - **映射**：根据掩码值，从图块集 (Tileset) 中选择对应的纹理（例如：转角、直墙、孤立墙等）。

## 2. 地形与导航系统 (Terrain & Navigation)

### 2.1 流场导航 (Flow Field Navigation)

`MapSystem` 类中包含了 `updateFlowField`、`getFlowDirection` 等方法，实现了完整的流场寻路系统。系统通过 `m_flowField` 和 `m_distanceField` 数据结构实现，支持动态更新。

 为了支持海量怪物（10,000+）的高性能寻路，摒弃传统的 A* 算法，采用 **流场 (Flow Field)** 技术。

 - **目标图 (Integration Field)**：以玩家为目标点，计算全图每个格子到玩家的"距离代价"。
 - **向量场 (Vector Field)**：根据目标图，计算每个格子指向"更低代价邻居"的方向向量。
 - **群体移动**：所有怪物只需查询所在格子的向量即可获得移动方向，无需单独计算路径。

### 2.2 地形交互 (Terrain Interactions)

地形由 `Tile::Type` 枚举表示：`WALL`、`FLOOR`、`DOOR`、`STAIRS_UP`、`STAIRS_DOWN`。`Tile::isWalkable()` 在类型不为 `WALL` 时返回 true。

- **地板 (FLOOR)**：标准移动速度。
- **墙壁 (WALL)**：不可通行；标记 `isAirWall` 的墙壁在逻辑上仍不可通行，仅在渲染层显示背景而非墙壁纹理。
- **门 (DOOR)**：可通行瓦片，供关卡结构使用。
- **楼梯 (STAIRS_UP / STAIRS_DOWN)**：入口与出口标记瓦片，`LevelManager` 通过扫描 `STAIRS_DOWN` 放置传送门。
- **地形修正**：摩擦等移动速度修正由群落 `features` 中的 `friction_mod`（`frictionMultiplier`）表达，而非独立瓦片类型。

## 3. 敌人生成与管理 (Enemy Spawning & Management)

### 3.1 种族与群聚 (Races & Clustering)

`EnemySpawnSystem` 依据 `BiomeConfig::enemyPool` 确定本关卡可用种族，并按“据点”群聚生成怪物。

 - **种族选择**：`selectRace` 将 `enemyPool` 全量解析为可用种族列表（不做 2-4 族的子集抽取），每个群聚生成时等概率随机选取一个种族；`enemyPool` 中重复出现的名称会提高对应种族权重。未知名称记录警告并忽略，列表为空时回退到 `{UNDEAD, DEMON}`。
 - **群聚生成**：基于“据点”生成怪物，而非均匀分布。基础据点数为 `(width * height) / CLUSTER_DENSITY_DIVISOR`（`CLUSTER_DENSITY_DIVISOR = 200`），再乘以难度密度系数，并限制为不超过 `max(1, maxEnemies / 5)`；单个据点敌人数量在 `MIN_CLUSTER_ENEMY_COUNT = 5` 与 `MAX_CLUSTER_ENEMY_COUNT = 12` 之间（乘以密度系数，上限 1.5 倍）；据点成员在半径 `SPAWN_RADIUS_MIN = 2` 至 `SPAWN_RADIUS_MAX = 4` 的范围内散开。据点中心需落在 `FLOOR` 瓦片上，最多尝试 20 次。
 - **敌人原型**：群聚内成员按 Warrior 40%、Archer 30%、Tank 15%、Assassin 10%、Mage 5% 的比例抽取。
 - **敌人规模**：战斗地图的 `maxEnemies` 来自群落配置，并钳制到 `[BIOME_MAX_ENEMIES_MIN = 150, BIOME_MAX_ENEMIES_MAX = 5000]`。
 - **精英怪**：生成时按稀有度掷点，`BOSS_CHANCE = 0.002`、`ELITE_CHANCE = 0.02`、`CHAMPION_CHANCE = 0.01`，其余为普通怪；生命倍率分别为 BOSS 15.0、精英 5.0、冠军 2.5 倍。

### 3.2 性能优化：休眠系统 (The Dormant System)

 `EnemySpawnSystem` 基于玩家距离执行动态生成与销毁，通过 `m_activationDistance` 和 `m_deactivationDistance` 参数控制敌人的激活与休眠范围；构造时分别设为 `DEFAULT_ACTIVATION_DISTANCE = 1200` 与 `DEFAULT_DEACTIVATION_DISTANCE = 2000`。

 解决"全图大量敌人"与"性能"矛盾的核心方案。

 - **数据层与实体层分离**：
   - **生成阶段**：地图加载时，只生成轻量级的"怪物数据"（位置、类型、等级），不创建游戏实体。
   - **激活 (Spawn)**：当玩家靠近数据点一定范围（激活范围）时，根据数据创建真正的游戏实体（Entity）。
   - **休眠 (Despawn)**：当实体离开玩家一定范围（卸载范围）时，销毁实体，将其状态（如剩余血量）写回数据层。
 - **低频模拟**：处于休眠状态的怪物不进行复杂的 AI 计算，仅保留极简的逻辑（或完全静止）。

## 4. 关卡生命周期 (Level Lifecycle)

`LevelManager` 管理关卡上下文（地图网格、怪物数据列表、掉落物列表，以及敌人生成系统与战争迷雾系统）的创建、更新与销毁，并通过 `prepareLevel` 在后台异步生成、`activateLevel` 在准备完成后接入主线程。城镇地图尺寸为 `DEFAULT_MAP_WIDTH x DEFAULT_MAP_HEIGHT = 128 x 128`；战斗地图尺寸为 `WORLD_WIDTH / GRID_TILE_SIZE x WORLD_HEIGHT / GRID_TILE_SIZE = 500 x 500`。

 - **关卡上下文**：包含地图网格、怪物数据列表、掉落物列表等。
 - **场景切换**：
   1. 玩家触发传送门。
   2. 销毁当前关卡上下文（清理所有实体和资源）。
   3. 异步准备新的关卡上下文并显示加载界面。
   4. 加载完成后应用地图与敌人，淡入新场景。
 - **传送门流程**：`LevelManager` 扫描 `STAIRS_DOWN` 瓦片生成传送门。当前群落为城镇时使用 `PortalType::DimensionalGate`（交互半径 40），否则使用 `PortalType::NextLevel`（交互半径 25）。
   - `NextLevel`：若存在裂痕完成确认则等待玩家选择；若维度已激活则调用 `AdvanceRiftLayer` 推进裂痕层级；否则放置 `PendingMosaicEditorTag` 进入 Mosaic 流程。
   - `DimensionalGate`：放置 `PendingDimensionalGateTag`，触发维度之门选择流程。
   - 进入城镇时记录裂痕出口位置并执行自动存档。
