# 2D 暗黑Like Roguelite RPG - 装备与存储设计 V0.3

## 1. 游戏核心概念 (Core Concept)

- **类型**：2D 动作 RPG + Roguelite
- **风格**：暗黑幻想 (Dark Fantasy)，利用AI生成暗黑风格素材
- **核心循环**：随机地图战斗 -> 搜刮资源(Loot) -> 角色成长(Build) -> 传送门抉择(Risk/Reward)

## 2. 角色成长系统 (Progression System)

### 2.1 被动技能体系 (Passive Skills)

摒弃复杂的主动技能树，采用“升级随机三选一”的Roguelite模式。

- **获取方式**：角色升级时触发，暂停游戏，弹出UI供玩家从3个随机选项中选择1个。
- **槽位限制 (Skill Limit)**：
  - 设定一个**最大被动技能数量上限**（例如：6个或8个）。
  - **替换机制**：当槽位已满且玩家选择了新的技能时，必须选择丢弃旧技能列表中的一个进行替换。
  - **升级机制**：如果随机到的技能是已拥有的，选择它将提升该技能的等级（Level Up），增加数值效果，不占用新槽位。

### 2.2 技能库设计思路

- *基础类*：增加攻击力、攻速、移速。
- *触发类*：攻击时X%几率触发闪电链/爆炸/流血。
- *生存类*：生命低于30%时生成护盾。
- *特殊类*：将一种伤害类型转化为另一种（例如：物理伤害转为火焰伤害）。

## 3. 装备与物品系统 (Itemization)

### 3.1 装备部位 (Equipment Slots)

共计 9 类 10 个槽位（双手占用主副手）：

1. **主手 (Main Hand)**：单手剑、斧、锤 / 双手剑、杖（占用副手）
2. **副手 (Off Hand)**：盾牌、法球、箭袋
3. **头盔 (Head)**
4. **护肩 (Shoulder)**
5. **胸甲 (Chest)**
6. **手套 (Hands)**
7. **护腿 (Legs)**
8. **鞋子 (Feet)**
9. **项链 (Neck)**
10. **戒指 (Ring)** x2

### 3.2 稀有度分级 (Rarity Tiers)

从低到高，对应不同的颜色和词条数量/强度：

1. **普通 (Common)** - 白
2. **魔法 (Magic)** - 蓝
3. **稀有 (Rare)** - 黄
4. **罕见 (Uncommon/Ancient)** - 橙
5. **套装 (Set)** - 绿（集齐触发额外技能）
6. **崇高 (Exalted)** - 紫（至少拥有一条 T6 以上的超阶词缀，无法通过锻造制作）
7. **独特 (Unique)** - 暗金（拥有专属特效和传奇潜能 LP）
8. **传奇 (Legendary)** - 红（由独特装备融合崇高装备后诞生，继承了词缀的红装）

### 3.3 属性体系 (Attributes)

- **基础属性**：攻击力、防御力、生命值、魔法值。
- **工艺属性**：
  - **锻造潜能 (Forging Potential)**：用于锻造消耗，归零后装备锁定。
  - **传奇潜能 (Legendary Potential)**：仅限独特装备，决定能从崇高装备吸收几条词缀。
  - **孔洞 (Sockets)**：用于镶嵌符文或宝石。
- **攻击属性**：暴击率 (Crit Rate)、暴击伤害 (Crit Dmg)、攻击速度 (Atk Speed)。
- **伤害类型**：物理、魔法、火焰、冰霜、闪电、毒素（用于计算抗性）。
- **特殊词条**：
  - **装备技能 (Equip Skill)**：装备赋予的额外被动技能（如：“穿戴此鞋时，移动留下火焰路径”）。
  - 技能等级加成（如：“所有火焰技能等级 +1”）。

## 4. 关卡与传送门系统 (Map & Portals)

### 4.1 地图流程

- **生成**：随机生成地形（房间+通道），布满怪物。
- **通关条件**：击败特定数量敌人 或 击杀地图Boss。
- **结算**：生成3扇传送门。

### 4.2 局内经济 (In-Run Economy)
金币不仅用于局外解锁，在单局游戏中也有重要作用：
- **流浪商人 (Merchant)**：随机生成。出售当前等级的装备（价格昂贵）、药水、鉴定卷轴。
- **贪婪祭坛 (Shrine of Greed)**：献祭金币，获得持续整局的 Buff（如：金币掉落翻倍，但受到的伤害增加）。
- **重铸铁砧**：花费金币刷新装备的一条随机词缀。

### 4.3 传送门机制 (The Choice)

- **红色传送门（力量/挑战）**：强力怪物，高掉率武器。
- **蓝色传送门（财富/生存）**：陷阱环境，高掉率防具/金币。
- **紫色传送门（混沌/变数）**：随机Buff/Debuff，特殊通货或神话物品几率。

## 5. 存储与物品管理系统 (Inventory & Storage)

### 5.1 死亡惩罚与继承 (Death Mechanics)

游戏提供基于风险偏好的死亡惩罚分级（可在基地设置或通过“契约”道具改变）：

1.  **标准模式 (Standard - Default)**：
    *   **丢失**：当前背包内未存入仓库的所有物品、当前局获得的经验值/等级。
    *   **保留**：角色身上**已装备**的物品、仓库内的物品、永久解锁的被动特质。
    *   **耐久惩罚**：已装备物品耐久度 -10%。
2.  **硬核模式 (Hardcore / Roguelite)**：
    *   **丢失**：**角色永久死亡**。角色身上的装备全部掉落（如果有多人模式）或消失。
    *   **保留**：仅仓库（公共储物箱）内容。
3.  **休闲/练习模式 (Casual)**：
    *   **丢失**：本次冒险获得的金币 -50%。
    *   **保留**：一切。

### 5.2 物品堆叠规则

- **不可堆叠**：装备（武器、防具、饰品）、特殊任务道具、背包容器本身。每个占用 **1个格子**。
- **可堆叠**：金币（或不占格子，直接作为数值存储）、消耗品（药水、卷轴）、制作材料。
  - **堆叠上限**：推荐 **999** 或 **1000**（便于UI显示，避免4位数溢出格子显示区域）。

### 5.2 背包系统 (Player Inventory)

采用 **“核心背包 + 扩展容器”** 的模式。

- **初始空间**：默认拥有 **1页** 基础背包（建议大小：40格，5x8布局）。
- **扩展机制 (Bag Slots)**：
  - 界面底部提供 **3个容器槽位**。
  - 玩家可以将获得的“背包道具”装备到这3个槽位中，点击对应的标签页即可切换查看额外的存储空间。
- **容器获取与限制**：
  - **商人出售**：提供基础扩充。最大容量限制为初始页面的 **50%**（例如：最大20格）。
  - **怪物掉落**：作为稀有战利品掉落。容量随机，最大可达初始页面的 **100%**（例如：最大40格）。这也成为了刷宝的一环。

### 5.3 仓库系统 (Stash / Warehouse)

- **账号共享**：建议设定为账号下所有角色共享（方便小号开荒），或者是“个人仓库+共享页”混合模式。
- **扩充机制**：
  - **初始**：1页（建议大小：80格，远大于背包）。
  - **解锁**：通过消耗**金币 (Gold)** 购买新的标签页。价格呈指数级增长，作为游戏后期的主要**金币回收手段 (Gold Sink)**。

### 5.4 交互与体验优化 (UX/QoL)

- **智能排序**：一键整理，按 类型 > 稀有度 > 等级 排序。
- **快速转移**：Ctrl+点击（或类似操作）在背包与仓库间快速存取。
- **过滤/搜索**：仓库页应支持简单的文本过滤（如输入“剑”只高亮剑类物品），这对后期管理海量装备至关重要。
- **战利品过滤 (Loot Filter)**：(详见第7章) 允许玩家设置规则以自动屏蔽或高亮特定掉落。

## 6. 技术架构实现概念 (Technical Implementation Concepts)

### 6.1 数据驱动的物品定义 (Data-Driven Item Definition)

为了支持海量装备和随机词条，物品系统不使用传统的面向对象继承，而是采用 **ECS 组件化** 和 **享元模式 (Flyweight Pattern)**。

- **静态数据 (Item Definition)**：
  - 存储在 JSON 配置文件中。
  - 包含：基础名称、图标路径、基础属性区间、允许出现的词条类型。
  - 游戏启动时加载到资源管理器中，作为只读模板。
  - **底材定义**：区分“短剑”、“水晶剑”、“巨神之刃”，它们的基础攻速和孔数上限不同。

- **动态实例 (Item Instance)**：
  - **地面物品**：作为独立的 ECS 实体存在，拥有渲染组件、物理组件（拾取碰撞）和物品数据组件。
  - **背包物品**：为了性能，背包内的物品简化为轻量级的数据结构，存储：
    - `InstanceID`, `DefinitionID`
    - `AffixList` (前缀/后缀, 包含 Tier 和 Value)
    - `ForgingPotential` (int)
    - `Sockets` (List<RuneID>)

### 6.2 库存与容器逻辑 (Inventory Logic)

- **扁平化存储**：`InventoryComponent` 内部维护一个固定大小的数据集合，直接映射 UI 的网格。
- **堆叠处理**：在拾取逻辑中，优先检查背包内是否存在相同的物品定义且未达到堆叠上限，进行数量合并；否则占用新格子。
- **引用管理**：`EquipmentComponent`（装备槽）不存储物品实体，而是存储指向背包中特定物品的索引或唯一 ID，确保数据的一致性。

### 6.3 战利品生成算法 (Loot Generation Algorithm)

生成器不依赖硬编码，而是基于权重表：

1.  **输入**：怪物等级、怪物稀有度、玩家的“寻宝值” (Magic Find)。
2.  **判定**：
    - 先判定是否掉落（Drop Rate）。
    - 再判定物品稀有度（权重随机）。
    - 最后根据稀有度，从词条池中随机抽取 N 个属性修饰符。
3.  **实例化**：创建一个新的物品实体，将其属性“烘焙”到组件中，并抛射到地图上。

## 7. 战利品过滤系统 (Loot Filter System)

### 7.1 设计目标
随着游戏进程推进，掉落物品数量将呈指数级增长。为了防止“垃圾”装备干扰玩家视野并降低性能，需要一个可配置的过滤系统。

### 7.2 核心机制
- **过滤器规则 (Rules)**：由一系列有序规则组成，从上到下执行。一旦匹配某条规则，即执行对应操作并停止检测（类似防火墙规则）。
- **判定时机**：物品掉落生成实例后，在 `DropSystem` 或 `RenderSystem` 中进行检测。
- **可配置性**：支持 JSON 文件导入/导出，方便社区分享。

### 7.3 过滤条件 (Conditions)
一条规则可包含多个条件的“与”逻辑（必须全部满足）：
1.  **稀有度 (Rarity)**：
    - `MIN_RARITY`: 大于等于某品质
    - `MAX_RARITY`: 小于等于某品质
    - `EQUAL_RARITY`: 等于某品质
2.  **物品类型 (Item Type)**：
    - `TYPE`: 武器、防具、饰品、材料、金币
    - `SUBTYPE`: 剑、斧、头盔、戒指等
3.  **物品等级 (Item Level)**：区间判断 (Min/Max)。
4.  **特定词缀 (Affix)**：是否包含特定词缀（如“CritRate”），或词缀数量（如“至少3条词缀”）。
5.  **底材 (Base Type)**：匹配特定的底材名称（如“Mithril Blade”）。

### 7.4 过滤行为 (Actions)
1.  **显示 (SHOW)**：正常渲染，默认字体和颜色。
2.  **隐藏 (HIDE)**：完全不渲染模型和UI标签，不可拾取（或仅按 Alt 键强制显示）。
3.  **高亮 (EMPHASIZE)**：
    - 修改掉落光柱颜色（RGB）。
    - 加大 UI 标签字号。
    - 播放特殊音效（如“Legendary Drop Sound”）。
4.  **小地图图标 (MINIMAP_ICON)**：在小地图上显示特殊图标（星星、圆点）。

### 7.5 数据存储与 API
- **配置文件**：`assets/data/loot_filters/default.json`
- **JSON 结构示例**：
  ```json
  {
    "name": "Endgame Starter",
    "description": "Hides normal/magic items, highlights rares+",
    "rules": [
      {
        "name": "Hide Trash",
        "action": "HIDE",
        "conditions": {
          "max_rarity": "MAGIC",
          "min_level": 10
        }
      },
      {
        "name": "Highlight Exalted",
        "action": "EMPHASIZE",
        "color": [255, 0, 255],
        "conditions": {
          "min_rarity": "EXALTED"
        }
      }
    ]
  }
  ```
