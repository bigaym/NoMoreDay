# 技术架构与实现路线图 (Technical Architecture & Roadmap) V0.5

## 1. 核心技术栈 (The High-Performance Stack)

本项目旨在构建一个基于 **C++20** 的高性能、数据驱动（Data-Oriented）的游戏引擎，目标是在普通硬件上支持同屏数千单位的实时模拟与渲染。

| 模块 | 选型 | 来源/获取方式 | 核心职责 |
| :--- | :--- | :--- | :--- |
| **语言标准** | **C++20** | 编译器支持 | Modules, Concepts, Coroutines, Ranges. |
| **内存分配** | **mimalloc** | FetchContent (Microsoft) | 替换全局 `new/delete`，消除多线程内存分配锁竞争。 |
| **架构核心** | **EnTT** | FetchContent | 极速 ECS (Entity Component System)，保证数据局部性 (Cache Locality)。 |
| **并发调度** | **Taskflow** | FetchContent | 管理帧循环的有向无环图 (DAG)，实现任务级并行 (Task Parallelism)。 |
| **渲染后端** | **Raylib** | FetchContent | 轻量级 OpenGL 抽象，提供高性能 Batching 渲染接口。 |
| **GPGPU**   | **OpenGL 4.3 Compute** | Raylib RLGL | 通过 SSBO (Shader Storage Buffer Object) 实现海量粒子的物理与流场计算。 |
| **数据结构** | **ankerl::unordered_dense** | FetchContent | 替代 `std::unordered_map`，提供 3-5 倍的查找性能。 |
| **SIMD 计算** | **xsimd** | FetchContent | 封装 SSE/AVX 指令集，用于物理碰撞和距离计算的向量化。 |
| **日志系统** | **spdlog** | **本地路径** | 异步、零拷贝的高性能日志记录。 |
| **序列化** | **nlohmann/json** | FetchContent | 配置文件与数据交换标准格式。 |

## 2. 系统架构设计 (Architecture Design)

采用 **混合架构 (Hybrid Architecture)**：外层为面向对象的系统管理器，内核为面向数据的 ECS。

### 2.1 内存模型 (Memory Model)
- **入口点 (Entry Point)**：在 `main` 函数的最开始加载 `mimalloc` 重载。
- **资源管理 (RAII)**：所有纹理、音频资源由 `ResourceManager` 单例管理，使用引用计数，杜绝内存泄漏。

### 2.2 帧循环与并发 (The Concurrent Game Loop)
利用 **Taskflow** 构建静态任务图，最大化 CPU 利用率。

```mermaid
graph LR
    Input[Input Polling] --> Logic
    
    subgraph "Parallel Logic (Taskflow)"
        Logic[Logic Start]
        Logic --> AI[AISystem (Behavior Trees)]
        Logic --> Phys[PhysicsSystem (Spatial Hash)]
        AI --> Combat[CombatSystem (Tag Pipeline)]
        Phys --> Combat
        Combat --> FlowField[GPU Flow Integration Prep]
    end
    
    FlowField --> Compute[GPU Compute Dispatch]
    Compute --> RenderPrep[RenderSystem (Culling)]
    RenderPrep --> Draw[GPU Draw (Main Thread)]
```

### 2.3 实体组件系统 (ECS Design)
- **Registry**：全局唯一的 `entt::registry` 存储所有游戏状态。
- **Entity**：仅是一个 `uint32_t` ID。
- **Components (POD Types)**：
  - `Transform` (pos, rot, scale) - **Hot Data** (频繁访问)
  - `Velocity` (vec2) - **Hot Data**
  - `SpriteRenderer` (texture_id, source_rect)
  - `CombatStats` (hp, armor, resistances)
  - `Tags` (Bitmask for damage/mechanic types)
- **Systems**：纯函数逻辑，接受 Registry 和 DeltaTime。
  - *优化策略*：使用 `entt::group` 或 `entt::view` 预排序热数据，配合 `xsimd` 批量处理。

## 3. 关键模块实现流程 (Implementation Strategy)

### 3.1 物理与碰撞 (Physics - Spatial Hashing)
**不使用 Box2D**。针对大量圆形单位，实现自定义的空间哈希。
- **算法**：将地图划分为 `CellSize` (如 64px) 的网格。
- **数据结构**：`ankerl::unordered_dense::map<int, std::vector<EntityID>>`。
- **流程**：
  1. 每帧清空 Grid。
  2. 并行遍历所有 `Collider` 组件，计算其所属 Cell ID，填入 Grid。
  3. 查询时，仅检查目标周围 9 个 Cell 内的实体。

### 3.2 GPU 驱动的视觉与流场 (GPU Visuals & Flow Field)
- **GPU Particle System**：使用 Compute Shader 更新粒子位置和生命周期，直接写入 SSBO，再通过 `glDrawArraysInstanced` 渲染，无 CPU 回读开销。
- **GPU Flow Field**：
  - **Cost Field**：CPU 每一帧（或低频）更新地形代价纹理。
  - **Integration Field**：Compute Shader 并行计算全图距离场。
  - **Flow Vector**：生成向量场纹理，供成千上万的怪物实体在 Vertex Shader 中直接读取移动方向（或者 CPU 读取回来越快）。

### 3.3 伤害流水线 (Damage Pipeline)
- **Tag-Driven**：所有伤害计算基于标签匹配。
- **Batch Processing**：使用 xsimd 批量计算同一种类技能对多个目标的伤害，极大优化 AOE 性能。
