# CombatV2 伤害结算运行说明

## 1. 运行模式

`DamagePipeline::Calculate` 为唯一结算路径，直接按 `base_pool` 与施法者属性烘焙结果结算，不存在候选路径或运行时回退开关。

`DamageRequest.is_simulation` 区分用途：

1. `is_simulation=false`：正常结算，按 `utils::ThreadSafeRandom` 抽取暴击，产出真实承伤。
2. `is_simulation=true`：用于施法者快照反算，暴击按期望值 `1 + P * (Mult - 1)` 处理，不做随机判定，也不落地承伤。

## 2. 事件派发

1. `DamagePipeline::Calculate` 在 `is_simulation=false` 且 `dispatch_damage_events=true` 时，于末尾以最终承伤值派发一次伤害事件。
2. `DamagePipeline::Execute` 先以 `dispatch_damage_events=false` 调用 `Calculate`，再由 `CombatSystem::ApplyDamage` 落地，随后在 `dispatch_damage_events=true` 时派发一次 `OnDealDamage`。
3. `is_simulation=true` 或命中被闪避时，`Execute` 不落地承伤也不派发事件。

## 3. 验证入口

`tests/integration/CombatDamagePipelineCutoverTests.cpp`（标签 `[Integration] CombatDamagePipelineCutover`）覆盖：

1. 非 simulation 请求直接按 `base_pool` 结算，不保留双主路径。
2. `HazardEnvironment` 无攻击者时仍以 base pool 结算。
3. 无效请求返回零，base pool 为空时回退。
4. `Execute` 在非 simulation 下按 `dispatch_damage_events` 决定是否派发事件。
