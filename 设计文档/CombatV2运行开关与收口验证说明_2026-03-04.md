# CombatV2 运行开关与收口验证说明（2026-03-04）

## 1. 运行模式（单向）

当前 `DamagePipeline::Calculate` 已切换为单向策略：

1. 非 simulation 请求直接进入候选路径（`CandidateOnly`）。
2. simulation 请求（`is_simulation=true`）仍保持现有 simulation 计算路径。

说明：不再保留运行时回退/双跑开关策略。

## 2. 回归验证范围

本轮补充验证覆盖了 `DamagePipeline` 真实入口，而不仅是 facade 直测：

- `DamagePipeline::Calculate`
  - 非 simulation 请求直接走 candidate 结果。
- `DamagePipeline::Execute`（非 simulation）
  - `dispatch_damage_events=false`：不派发 `OnDealDamage`。
  - `dispatch_damage_events=true`：派发一次 `OnDealDamage`。

## 3. 已知限制（当前阶段）

- 候选路径仍为阶段性 stub，严格 parity 下存在预期差异。
- 评估 parity 结果时，应区分：
  - strict mismatch（预期可见）
  - tolerance match（在阈值内）

## 4. 发布与联调检查清单

1. 发布前确认单向候选路径与当前测试基线一致。
2. 至少执行：
   - `./bin/NoMoreDayTests.exe --test-case="[Integration] CombatV2Cutover*"`
   - `./bin/NoMoreDayTests.exe --test-case="[Integration] CombatV2DualRunParity*"`
3. PR/变更说明中显式写明：
   - 非 simulation 为 candidate-only 的单向策略；
   - 候选路径当前为 stub，严格 mismatch 为已知阶段性现象。
