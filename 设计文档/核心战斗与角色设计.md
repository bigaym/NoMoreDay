## 1. 构筑哲学（保持不变）

NoMoreDay 仍采用三层构筑体系：

1. 技能专精树：定义单技能形态变化、标签变化、触发逻辑。
2. 虚空星盘：提供全局被动、关键天赋与构筑方向。
3. 标签驱动：技能/装备/天赋通过统一标签进入同一结算合同。

差异点：战斗底层已从“概念型流水线”升级为“合同化流水线”，所有构筑变化最终都通过 `DamagePipeline` 一致执行。

## 2. 角色战斗执行模型

### 2.1 帧序约束

战斗逻辑必须服从统一帧序：

`Input -> Player Movement -> AI -> Combat -> Spatial Grid Rebuild -> Physics -> Render`

### 2.2 战斗子系统职责

1. `SkillSystem`：施法生命周期、触发派发、合同参数注入（含 `trigger.effectiveness`）。
2. `EffectSystem`：Buff/Debuff/DoT 调度，DoT 必须落地承伤。
3. `DamagePipeline`：唯一数值入口，输出最终承伤与语义标签。
4. `CombatSystem`：承伤落地、生命屏障结算、死亡处理。
5. `AilmentEngine`：异常状态合同化（叠层/刷新/覆盖/免疫）。
6. `SummonSystem`（分层）：生命周期、AI、战斗桥接与归因。
7. `ProcBudgetManager`：高频收益与事件限流。

## 3. 伤害与防御口径

### 3.1 统一伤害合同

```text
FinalDamage = ((Base + Added * AddedEff) * (1 + Increased) * More * TriggerEff) * Mitigation
```

其中：

1. `AddedEff` 来自技能数据 `added_damage_effectiveness`
2. `TriggerEff` 来自技能合同 `trigger.effectiveness`
3. `Mitigation` 由防御合同按固定顺序提供

### 3.2 防御合同顺序

1. 命中/闪避
2. 格挡
3. 护甲/抗性
4. 全局减伤
5. 屏障吸收
6. 生命结算

## 4. 反馈与可读性

1. 事件可信性：显示伤害、日志伤害、真实扣血必须一致。
2. 打击感：特效、音效、震屏继续由渲染与音频系统负责，但事件来源必须是合同化事件。
3. 可解释性：构筑面板与遥测指标支持定位伤害来源、触发链和预算命中情况。

## 5. 角色成长与流派边界

### 5.1 资源机制

1. 生命、法力、屏障为基础资源。
2. 职业机制资源（如剑意）可以扩展，但不得绕过战斗合同直接改伤害。

### 5.2 流派目标

vNext 以四类主流派为平衡目标：

1. 直伤
2. DoT
3. 召唤
4. 触发

发布评审以四流派 KPI 而非单流派峰值作为准入依据。

## 6. 职业与专精约束

1. 主职业决定起点与初始技能包。
2. 专精提供机制转化，但新增机制必须声明合同字段（标签、effectiveness、触发约束、预算影响）。
3. 任何“例外机制”都必须可被 `combat_release_gate` 检测。

## 7. 实施与维护规则

1. 设计改动先更新合同文档，再更新技能配置与代码。
2. 新增职业/专精机制时同步更新：
- `设计文档/职业被动和技能设置.md`
- `设计文档/怪物和AI设计.md`
- `设计文档/局外成长与终局玩法.md`
3. 若发现本文与实现不一致，以“修实现”为默认流程，不通过降级文档掩盖偏差。
